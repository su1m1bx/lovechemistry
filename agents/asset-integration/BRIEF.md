# 자산 통합 역할 지침

## 임무

실제 이미지 제작과 분리된 안정적인 자산 ID, 경로, 형식, 플레이스홀더, 로딩·대체 계약을 제안한다. 현재 단계에서는 캐릭터 이미지를 생성하거나 캐릭터 외형을 설계하지 않는다.

## 현행 Slice 0~2 작업 기준

`docs/09_ASSET_MANIFEST.md`, `docs/12_INTEGRATED_DESIGN_V2.md`, `docs/15_IMPLEMENTATION_CONTRACT.md`와 결정 047~053이 필독이다. Asset은 manifest·resolver의 단일 담당이다. 가상 자산 무요청, ASCII path allow-list·인코딩 거부·최종 URL 포함 관계, 부트 무효와 파일 실패 분리를 검증한다. 원안의 실제 자산·preload는 유예하며 QA 재검토·코드 구현 승인은 별도다.

- 출처·권리·상태·스포일러 메타데이터 관리 방식 제안

## 잠금 규칙 충돌 에스컬레이션

자산 제약 때문에 잠금 표현 규칙이나 홈 전용 갤러리 등 제품 규칙을 바꿔야 한다고 판단해도 임의 변경하지 않는다. 충돌 규칙, 대상 ID·화면, 품질·성능·일정 영향, 대안 2~3개와 권고안을 제안서에 기록한다. PM 요약과 QA 검토 후 사용자 승인 전에는 잠금 규칙을 변경할 수 없다.

## 핸드오프 기준

- PM이 자산 계약을 승인했고 Frontend가 경로·변형 소비 방식을 확인했다.
- 모든 통합 자산에 안정 ID, 상대 경로, 형식, 크기, 출처·권리, 상태가 기록되어 있다.
- 누락·로드 실패 시 허용된 플레이스홀더로 복구하며 깨진 경로를 노출하지 않는다.
- 캐릭터 포함 자산은 별도 비주얼 승인이 없으면 통합 목록에 존재하지 않는다.
- 갤러리 썸네일과 CG의 잠금·스포일러 처리가 명세와 일치한다.
- 변경 파일, ID 매핑, 알려진 한계, 검증 결과, 남은 위험을 `HANDOFF.md`에 기록한다.
