## 2. 의도한 해결안

### 2.1 구조 원칙

- 애플리케이션을 **홈 셸**과 **활성 게임 셸**로 명시적으로 분리한다.
- 홈 셸은 새 게임, 불러오기, CG 갤러리, 선택 설정을 제공한다.
- 활성 게임 셸은 Day·페이즈, VN, 자유시간, 장소, 공부, 주기율표, 미션, 인벤토리, 매점을 제공하되 CG 갤러리는 렌더링 대상과 내비게이션 모두에서 제외한다.
- 시험, 퇴학, 결말은 일반 오버레이가 아니라 이탈 방지와 결과 의미가 분명한 전용 흐름으로 다룬다.
- 주기율표는 같은 과학 정본을 읽는 조회·비교 도구로 만들고, UI 내부에 과학 사실을 복제하지 않는다.
- 주요 행동에는 결과뿐 아니라 시간 소비 여부, 선행 조건, 잠금 이유를 실행 전에 보여 준다. 실제 비용과 조건 값은 Game Systems 계약을 따른다.
- 기능 상태는 `사용 가능`, `잠김`, `완료`, `진행 중`, `비어 있음`, `오류`를 색상 이외의 텍스트·아이콘·형태로도 구분한다.

### 2.2 상위 정보 구조

```text
애플리케이션
├─ 홈 셸
│  ├─ 타이틀
│  ├─ 새 게임 / 플레이어 설정
│  ├─ 불러오기 / 저장 데이터 복구 안내
│  ├─ CG 갤러리
│  └─ 선택 설정(표시·접근성만, 음향 제외)
├─ 활성 게임 셸
│  ├─ Day 전환 / 하루 요약
│  ├─ VN 장면
│  ├─ 점심 자유시간
│  ├─ 방과 후 자유활동
│  ├─ 학교 장소 / 이벤트
│  ├─ 공부 / 함께 공부
│  ├─ 주기율표 / 원소 비교
│  ├─ 미션
│  ├─ 인벤토리
│  └─ 매점 인터페이스
└─ 강제 진행·종료 흐름
   ├─ Day 10·20·30 시험
   ├─ 시험 결과 / 퇴학 게임 오버
   ├─ 캐릭터 엔딩
   └─ 노멀 엔딩
```

## 3. 주요 화면 흐름

### 3.1 시작과 복귀

```text
타이틀
├─ 새 게임 → 이름 입력 → 남성 주인공 고정 안내 → 시작 확인 → Day 1 전환
├─ 불러오기 → 유효한 날짜 스냅샷 확인 → 복원 결과 → 해당 Day의 계약된 시작 지점
└─ CG 갤러리 → 목록 → CG 상세 → 갤러리 → 타이틀
```

- 주인공은 사용자 결정으로 남성 고정이며 성별 선택 컨트롤을 만들지 않는다. 이름은 사용자 입력으로 유지하고 남성 안내에서 주인공 외형·신체·복장을 발명하지 않는다.
- 손상·구버전 저장은 조용히 무시하지 않고 상태 담당자가 정의한 복구 또는 안전한 초기화 선택을 설명한다.
- 갤러리에서 활성 게임으로 직접 진입하는 경로는 두지 않는다.

### 3.2 일반 Day

```text
Day 전환
→ 아침 조회 VN
→ 오전 수업
→ 점심 자유시간 선택
→ 장소·공부·미션·관계 이벤트 중 시스템이 허용한 행동
→ 오후 수업
→ 방과 후 자유활동 선택
→ 장소·공부·미션·관계 이벤트 중 시스템이 허용한 행동
→ 귀가 확인
→ 하루 요약 및 Day 스냅샷 경계
→ 다음 Day
```

- 현재 `DAY NN / 30`과 페이즈를 활성 게임 셸에 지속적으로 표시한다.
- 선택 화면에는 남은 선택 기회 또는 비용 정보를 Game Systems의 공개 계약대로 표시한다.
- 귀가·하루 종료는 저장 경계에 영향을 줄 수 있으므로 확인 화면과 상태 담당 계약이 필요하다.

### 3.3 시험일과 종료

```text
Day 10·20·30 오후 수업 뒤
→ 시험 안내
→ 문항 진행
→ 미제출 확인
→ 채점
├─ 50점 이상, 보류 후보 없음 → 결과·해설 → 같은 Day 방과 후 → dayEnd
├─ 50점 이상, 보류 후보 있음 → 결과·해설 → 즉시 엔딩 후보 흐름
└─ 49점 이하 → 퇴학 결과 → GAME OVER → 타이틀

Day 30 dayEnd 뒤
└─ 캐릭터 엔드 미발생 회차 → 노멀 엔딩

캐릭터 엔드
└─ 효과 트랜잭션 완료 직후 자격 판정 → 단일 후보 또는 동시 자격 후보 중 한 명 → 실패 없는 최종 장면 → terminal
```

- `49`, `50`, `100`의 경계가 결과 화면과 흐름에서 오해 없이 드러나야 한다.
- UI는 호감도만 보고 캐릭터 엔딩을 성공으로 표시하지 않는다.
- 시험 도중 일반 게임 메뉴로 우회하거나 불러오기로 필수 시험을 건너뛰는 흐름을 제공하지 않는다.
- 제출 전 종료는 같은 Day 시작과 같은 고정 문항·순서로 돌아간다. 합격 제출 뒤에는 보류 후보가 없으면 같은 Day 방과 후, 있으면 동일 엔딩 후보 흐름으로 복원되고 실패 제출 뒤에는 terminal로 복원됨을 알린다. 시험 강제 체크포인트를 사용자 장면 저장 슬롯처럼 표시하지 않는다.
- 현재 시험 또는 도달한 필수 시험이 미완료면 엔딩 UI를 보류하고 시험을 우선한다. 50점 미만이면 후보보다 퇴학을 표시한다. 단일 후보는 최종 장면으로, 하나의 다인 효과가 만든 복수 후보는 그 자격 후보만의 한 명 선택으로 진행하며 정확히 하나의 엔딩만 확정한다. terminal 뒤 미래 시험·Day 진행은 제공하지 않는다.

## 4. VN 레이아웃 제안

### 4.1 공통 계층

1. 장소 배경 또는 비시각 플레이스홀더
2. 반신 캐릭터 스프라이트 또는 외형 중립 플레이스홀더
3. 장면 문맥 영역: Day, 페이즈, 장소
4. 대화 영역: 화자명, 본문, 계속 진행 신호
5. 선택지 영역: 선택 가능 여부와 잠금 이유
6. 보조 동작: 대화 기록, 텍스트 표시 설정, 주기율표 바로가기(장면에서 허용될 때만)

- 자동 진행, 음성, 음량 관련 컨트롤은 제안하지 않는다.
- 스프라이트는 반신과 표정 변화라는 표현 형식만 수용하며 위치·크기·외형·표정 목록은 확정하지 않는다.
- 장면 전환과 표정 변화는 모션 감소 설정에서 즉시 전환 가능해야 한다.
- 선택지는 대화 본문과 시각·구조적으로 분리하고 키보드 순서를 화면 순서와 일치시킨다.
- 과학 단어 도움말은 서사를 끊는 강제 팝업보다 사용자가 여는 짧은 설명을 우선하되, 사실값은 과학 정본에서 가져온다.

### 4.2 데스크톱

- 넓은 화면에서는 장면을 중심에 유지하고 영구 HUD가 스프라이트 얼굴이나 대화 영역을 침범하지 않게 별도 안전 영역을 둔다.
- 대화 상자는 화면 하단의 안정된 읽기 영역으로 두고 지나치게 긴 한 줄을 피한다.
- 선택지가 많아지면 장면 위에 흩뿌리지 않고 한 영역에서 스크롤하며, 첫 선택지로 자동 포커스하지 않는다.

### 4.3 모바일

- 세로 방향을 기본 사용 사례로 지원한다. 배경·스프라이트가 축소되어 정보를 잃더라도 대화와 선택의 읽기·조작성을 우선한다.
- Day·페이즈는 축약 가능한 상단 문맥 영역에 유지하고, 보조 도구는 명시적 메뉴로 접는다.
- 가상 키보드가 이름 입력과 대화 UI를 가리지 않도록 뷰포트 변화에 대응한다.
- 대화 본문과 선택지를 동시에 표시하기 어려운 높이에서는 선택지 패널을 독립 스크롤 영역으로 제공하되 본문 마지막 문맥을 남긴다.

## 5. 핵심 기능 UX

### 5.1 주기율표

- 1~20번 원소를 실제 주기율표의 족·주기 위치 관계가 보이도록 배치한다.
- 범위 밖 칸은 학습 대상으로 오인되지 않게 비대화식 구조 또는 설명 처리하며, 거짓으로 압축한 표를 만들지 않는다.
- 원소 셀에는 최소 원자번호와 기호를 제공하고, 선택 시 한국어명, 영어명, 족, 주기, 전자껍질별 전자배치, 승인된 원자가전자 정보를 상세 패널에서 보여 준다.
- 이름·기호·원자번호 검색과 원소 1~20 핵심 사실은 기본 제공한다. 족·주기 필터는 숙련도 1, 두 원소 비교는 2, 복합 비교는 3에서 활성화한다. 비교는 같은 정본의 값을 보여 주고 서사적 성격을 과학 사실과 섞지 않는다.
- 모바일에서는 표를 임의 카드 목록으로 대체해 공간 관계를 잃지 않는다. 가로 스크롤 가능한 표와 선택 원소 상세를 조합하고 현재 스크롤 위치·행·열 의미를 제공한다.
- 미션에서 열었을 때는 관련 단서로 돌아가는 명시적 `미션으로 돌아가기` 문맥을 제공한다. 정답을 자동 노출하는 기능은 시스템 계약 없이는 넣지 않는다.
- 시험 중 주기율표는 답안·문항 순서·현재 문항을 유지하는 오버레이로 제공한다. 기본 공간 배열과 원소 1~20의 원자번호, 기호, 한국어·영어 이름, 족, 주기, 전자껍질별 전자배치, 승인된 원자가전자만 표시한다. 검색·숙련도 기반 필터·두 원소 비교·복합 비교·미션/대화 힌트·오답 진단은 비활성이고, 닫으면 동일 문항과 호출 포커스로 돌아간다. 조회는 행동 비용·자동 답 선택·점수 보정이 없다.

### 5.2 공부와 함께 공부

- 공부 주제를 개념, 현재 학습 상태, 예상 활용처로 탐색한다.
- 각 주제는 숙련도 `0~3`, 마지막 상승 출처, 다음 단계에 필요한 행동을 상태 담당 계약에 맞게 표시한다.
- 시작 전 시간·행동 비용, 선행 지식, 함께 공부 가능한 캐릭터를 공개 계약대로 보여 준다.
- 함께 공부는 일반 메뉴의 캐릭터 보너스 선택으로 축소하지 않고 VN 장면과 상호작용을 거치는 흐름으로 연결한다.
- O가 강한 축임을 지원하되 O만 노출하는 전용 구조로 만들지 않는다.
- 완료 후 공개된 지식, 시험 준비 변화, 미션·대화 활용 가능성을 요약하되 효과를 UI가 계산하지 않는다.
- 무료 일과 수업은 `0→1`만 가능하고 `1+`에서는 복습·진단임을 표시한다. `2·3`은 점심·방과 후 행동 슬롯을 쓰는 혼자·함께 공부로만 획득하며 시험 공부 행동을 무료 수업으로 대체해 보이지 않는다.
- 단계 효과는 `1 = 시험 범위 체크리스트·기초 오답 진단·족/주기 필터`, `2 = 대화 해석 단서·미션 비정답형 힌트·두 원소 비교`, `3 = 복합 비교·범위 내 심화 오답 설명·일부 더 나은 해결/대화 선택 이해 또는 해금`으로 구분한다.
- 원소 1~20 핵심 사실은 숙련도와 무관하게 주기율표에서 기본 조회하며, 숙련도가 시험 점수나 정답을 자동 보정한다고 표현하지 않는다.

### 5.3 시험

- 시험 시작 전 대상 Day, 평가 범위, 진행 방식, 50점 미만 퇴학 규칙을 명시한다.
- 한 화면 한 문항을 기본안으로 권고한다. 현재 문항 번호, 전체 문항 수, 답변 여부, 제출 전 검토 상태를 제공한다.
- 정답은 색만으로 구분하지 않고 텍스트와 아이콘을 함께 사용한다.
- 시간 제한은 잠금 규칙에 없으므로 도입하지 않는다.
- 결과에는 점수, 생존·퇴학 판정, 승인된 해설을 제공한다. 해설의 과학 사실은 정본과 연결되어야 한다.

### 5.4 매점

- 학교 지도에 매점을 장소 노드로 만들지 않고 활성 게임 셸의 버튼으로 연다.
- 상품 목록에는 이름, 보유 수량, 가격·재화, 구매 가능 여부와 불가 이유를 표시한다. 정확한 재화 체계와 가격은 Game Systems 의존성이다.
- 구매 전후에 수량과 비용을 확인하며, 연속 입력으로 중복 구매되지 않게 처리한다.
- 미션 관련 상품 표시는 스포일러와 자동 정답 노출을 피하도록 Narrative·Systems 계약을 따른다.

### 5.5 인벤토리

- 선물, 미션, 학교생활, 공부 관련 분류를 데이터가 제공하는 범위에서 필터링한다.
- 항목 상세에는 이름, 수량, 용도 설명, 사용 가능 문맥과 불가 이유를 표시한다.
- 장비 슬롯, 능력치 비교, 희귀도 중심의 복잡한 RPG 구조는 도입하지 않는다.
- 현재 장면에서 사용 가능한 아이템만 `사용` 동작을 활성화하며 효과와 소비 여부는 Systems가 결정한다.

### 5.6 미션

- `locked`, `available`, `active`, `readyToTurnIn`, `completed`, `failed`, `expired` 일곱 상태를 최종 미션 상태 계약대로 손실 없이 표시한다.
- 목록에는 요청자, 짧은 목적, 알려진 단서, 관련 장소·아이템·학습 주제, 기한이 실제로 존재할 경우 기한을 표시한다.
- 상세 화면은 `요청 → 확인한 단서 → 가능한 다음 행동 → 결과`의 이해를 돕되 숨겨진 조건이나 정답을 그대로 공개하지 않는다.
- 장소, 공부, 주기율표, 인벤토리로 이동한 뒤 미션 상세로 돌아갈 수 있는 문맥 이동을 제공한다.
- Ne의 히든 조건은 발견 전 일반 미션이나 잠긴 슬롯으로 노출하지 않는다.

### 5.7 장소와 자유시간

- 점심과 방과 후 선택 화면은 현재 페이즈, 가능한 장소·행동, 예상 비용, 잠금 이유를 한곳에서 비교하게 한다.
- 장소가 기본 일곱 공간을 넘어 늘어나는 것을 UI 편의로 유도하지 않는다.
- 지도 그림은 필수 구조가 아니다. 접근 가능한 장소 목록 또는 의미 있는 공간 관계를 보존하는 선택 UI를 우선한다.
- 캐릭터 위치를 공개할 범위, 방문 전 이벤트 예고 수준, 행동 취소 가능 시점은 Systems·Narrative 계약을 따른다.

## 6. 홈 전용 갤러리 차단

갤러리 제한은 버튼을 숨기는 수준이 아니라 화면 전이 계약으로 보장해야 한다.

- 홈 셸에서만 `CG 갤러리` 진입 동작을 등록한다.
- 활성 게임 셸의 전역 메뉴, VN 보조 메뉴, 일시 메뉴, 결과 화면에는 갤러리 링크를 두지 않는다.
- 갤러리 화면 진입은 `HomeShell` 문맥에서만 허용한다. `runStatus` 하나만으로 허용 여부를 판단하지 않는다. 종료 상태라도 엔딩·결과 흐름에 머무는 동안은 홈이 아니기 때문이다.
- 활성 게임 또는 종료 결과 흐름에서 URL·브라우저 기록·개발 중 남은 링크로 갤러리 진입을 요청하면 갤러리를 렌더링하지 않고 직전 문맥을 유지한다.
- 갤러리는 `MetaState`의 해금 정보만 읽고 활성 `GameState`를 변경하지 않는다.
- 잠긴 CG는 승인된 비스포일러 대체 썸네일과 `미해금` 상태만 보여 주며 캐릭터·이벤트명을 통해 내용을 누설하지 않는다.
- 엔딩이나 CG 해금 직후에는 `갤러리에 추가됨`을 알릴 수 있지만 활성 게임에서 갤러리를 여는 동작은 제공하지 않는다.

## 7. 반응형 제안

정확한 아트 종횡비와 픽셀 크기는 Asset Integration 검토 전까지 확정하지 않는다. UI는 콘텐츠 중심 세 가지 동작 범위를 제안한다.

| 범위 | 잠정 기준 | 주요 동작 |
|---|---:|---|
| 소형 | `0~767px` | 단일 열, 하단 또는 접이식 보조 내비게이션, 전폭 대화·상세 패널, 주기율표 가로 스크롤 |
| 중형 | `768~1023px` | 주 콘텐츠 + 선택적 보조 패널, 오버레이보다 시트·분할 패널 우선 |
| 대형 | `1024px 이상` | 주 콘텐츠와 문맥 보조 패널 병렬, 최대 읽기 폭 제한, 장면 안전 영역 유지 |

- 브라우저 확대 `200%`에서 핵심 기능을 사용할 수 있어야 한다.
- 높이가 낮은 가로 모바일에서도 주요 버튼이 화면 밖에 고정되지 않아야 한다.
- 마우스 호버에만 정보를 두지 않는다.
- 화면 폭뿐 아니라 컨테이너 크기와 콘텐츠 길이에 견디는 구조를 우선한다.
- 긴 이름, 큰 글자, 한국어 줄바꿈, 영문 원소명 병기를 실제 데이터로 검증한다.

## 8. 접근성 제안

- 목표 기준은 WCAG 2.2 AA다.
- 모든 기능을 키보드만으로 수행할 수 있고 포커스 표시가 명확해야 한다.
- DOM 순서, 읽기 순서, 포커스 이동 순서를 일치시킨다.
- 모달·시트는 제목, 설명, 포커스 고정, 닫기, 닫은 뒤 원래 트리거 복귀를 제공한다.
- 선택지와 시험 답안은 실제 버튼·라디오 그룹 등 의미 있는 HTML 요소를 사용한다.
- 상태, 정답, 잠금, 호감 단계는 색상만으로 전달하지 않는다.
- 일반 텍스트와 UI 구성요소는 AA 명도 대비를 충족한다. 최종 색상은 비주얼 단계에서 별도 검증한다.
- 포인터 대상은 최소 WCAG AA 요구를 만족하고, 모바일 주요 동작은 권장 `44×44 CSS px` 수준을 목표로 한다.
- 움직임 감소 환경에서는 장면 전환, 스프라이트 변화, 결과 강조 애니메이션을 제거하거나 즉시 완료한다.
- 라이브 영역은 구매 결과, 저장 오류처럼 즉시 알려야 하는 변화에만 제한적으로 사용해 대사를 중복 낭독하지 않는다.
- 캐릭터 스프라이트는 장식이면 빈 대체 텍스트를 사용하고, CG는 스포일러 정책을 반영한 대체 설명 책임을 Asset Integration·Narrative와 합의한다.
- 플레이스홀더는 외형을 추측하는 대체 설명 대신 `캐릭터 이미지 준비 중`처럼 기능적 상태를 알린다.
- 음향이 없으므로 어떤 정보도 소리를 전제로 하지 않으며 음향 설정을 만들지 않는다.

## 9. 로딩·오류·빈 상태

- 초기 데이터 로딩: 화면 구조와 현재 작업을 예측할 수 있는 텍스트 상태를 제공한다.
- 자산 누락: `docs/09_ASSET_MANIFEST.md`의 명시적 `placeholderId`로 대체하고 무관한 실제 자산을 사용하지 않는다.
- 과학 데이터 누락: 사실을 추정해 표시하지 않고 해당 상세를 사용 불가로 처리하며 진단 가능한 오류를 남긴다.
- 저장 없음: 불러오기 화면에 빈 상태와 새 게임 복귀 동작을 제공한다.
- 저장 손상: 상태 담당 복구 정책과 데이터 삭제 영향, 취소 가능 여부를 설명한다.
- 목록 없음: 미션·인벤토리 각각 의미에 맞는 빈 상태를 제공하며 오류와 구분한다.
- 동작 실패: 중복 실행을 막고 입력값을 보존한 채 재시도 또는 안전한 복귀를 제공한다.

## 10. 기술 스택 후보와 추천

### 후보 비교

| 후보 | 장점 | 단점·위험 | GitHub Pages 적합성 |
|---|---|---|---|
| Vanilla TypeScript + Vite | 런타임 의존성이 작고 정적 산출물이 단순함 | 복잡한 화면·포커스·상태 전이의 일관성을 직접 관리해야 하며 콘텐츠 확장 시 유지보수 부담이 큼 | 높음 |
| Preact + TypeScript + Vite | 작은 번들, React 유사 개발 방식 | 팀·테스트 생태계와 일부 라이브러리 호환성을 추가 검증해야 함 | 높음 |
| React + TypeScript + Vite | 데이터 중심 화면, 조건부 셸, 접근성 테스트, 향후 콘텐츠 확장에 익숙한 생태계 | 기본 번들이 더 크며 의존성 절제가 필요함 | 높음 |

### 승인안

**React + TypeScript + Vite + CSS Modules**가 승인됐다.

- 홈 셸과 활성 게임 셸, 다수의 데이터 기반 화면, 대화·미션·시험 상태 표현을 명시적인 컴포넌트 계약으로 분리하기 쉽다.
- Vite의 `base`를 저장소 하위 경로에 맞춰 빌드 시 설정할 수 있다.
- 런타임 서버 없이 정적 파일로 배포할 수 있다.
- React Testing Library, Vitest, Playwright, axe 계열 도구로 키보드·포커스·화면 전이를 검증하기 쉽다.
- Vitest와 React Testing Library는 단위·컴포넌트 검증, Playwright는 핵심 흐름·GitHub Pages E2E, axe는 자동 접근성 검사에 사용한다. axe만으로 접근성 합격을 선언하지 않고 키보드·화면 낭독기 수동 검사를 병행한다.
- V1은 URL 라우터 없이 최상위 앱 상태로 화면을 전환한다. 브라우저 주소로 장면을 직접 열어 저장·시험·갤러리 가드를 우회하는 문제와 GitHub Pages의 SPA 폴백 문제를 줄인다.
- URL 공유가 향후 승인된 요구가 되면 별도 변경 결정으로 해시 라우팅을 검토한다. 일반 history 라우팅은 V1 계약이 아니다.
- 전역 상태 라이브러리는 State 제안 전 도입하지 않는다. 상태 담당 공개 계약이 단순하면 React 자체 상태 경계로 시작하고, 복잡성이 입증될 때만 별도 라이브러리를 검토한다.

### 제안 개발 의존성

아래 도구 조합은 승인됐으나 이 문서 작업에서는 설치하지 않는다.

- 런타임: `react`, `react-dom`
- 빌드·타입: `typescript`, `vite`, React용 Vite 플러그인
- 단위·컴포넌트 QA: `vitest`, `@testing-library/react`, `@testing-library/user-event`, `jsdom`
- E2E·배포 QA: `playwright`
- 접근성 자동 검사: `axe-core` 연동 도구

아이콘 라이브러리, UI 컴포넌트 키트, CSS 프레임워크, 라우터, 전역 상태 라이브러리는 초기 필수 의존성에서 제외한다. 시각 언어를 조기에 고정하고 번들을 키우는 것을 피하기 위해서다.

## 12. 외부 계약 의존성

- **Game Systems:** 페이즈별 허용 행동, 행동 비용, 공부 진행, 시험 문항 흐름, 재화·가격, 아이템 사용, 미션 상태와 종료 판정
- **State/Save:** 홈·활성 게임 판별, Day 스냅샷 요약과 경계, 저장 오류·마이그레이션 결과, `GameState`·`MetaState` 읽기/명령 인터페이스
- **Science:** 원소 1~20 정본, 용어, 전자배치 표시, 비교 가능한 필드, 문항 해설
- **Narrative:** 장면 길이·화자·선택지·대화 기록, 잠금 이유 공개 수준, 미션 단서, 스포일러 정책, CG 대체 설명
- **Asset Integration:** 원본 크기·종횡비, 안전 영역, 플레이스홀더 파일, 이미지 로딩·대체 텍스트 계약
- **QA:** 수용 기준, 지원 브라우저·기기 행렬, 자동 접근성 및 GitHub Pages 검증 범위

## 13. 가정과 미정 사항

- 주인공은 남성 고정이며 UI는 이름만 입력받고 `gender = male`을 소비한다. 외형은 계속 미정이다.
- 세부 취소 가능 시점과 최종 아이템 가격은 미정이다. 점심·방과 후 각 1행동과 시작 재화 3,000은 승인됐다.
- 시험은 고정 10문항·각 10점이고 시험 중 제한 기본 조회를 허용한다. 최종 문항 문구·선택지는 미정이다.
- 호감도 수치 전체를 항상 공개할지 단계만 공개할지는 미정이다. 어느 방식도 임계값 자체를 바꾸지 않는다.
- 대화 기록의 저장 범위, 텍스트 표시 설정의 메타 저장 여부는 미정이다.
- 정확한 CG 목록, 잠금 썸네일 문구, 대체 설명은 미정이다.
- 자산 픽셀 크기와 종횡비, 색상, 서체, 아이콘 스타일, 장식, 캐릭터 외형은 모두 미정이다.
- 목표 브라우저 최소 버전과 저사양 성능 예산은 QA·PM 결정이 필요하다.
- Systems와 State는 미션 7상태(`readyToTurnIn`, `expired` 포함)로 정렬됐다. UI는 상태를 임의 축약하지 않는다.
- 호감도는 게임플레이 상·하한과 clamp 없이 JavaScript 안전 정수로 검증한다. UI는 100 또는 다른 유한 최대를 전제로 한 게이지를 사용하지 않는다.
- V1 단일 활성 회차와 사용자 관점의 Day 시작 스냅샷을 기본으로 하며, 시험 합격 후 강제 체크포인트는 보류 후보가 없으면 같은 Day 방과 후를, 있으면 동일 후보 엔딩 흐름을 복원한다. 내부 이중 버퍼와 체크포인트를 복수 사용자 저장 슬롯처럼 노출하지 않는다.

## 15. 절충과 대안

### 15.1 화면 라우팅

- **안 A, 승인:** URL 라우터 없이 앱 상태로 화면 전환. 규칙 우회와 Pages 폴백 위험이 가장 작지만 URL 공유와 브라우저 뒤로 가기 지원이 제한된다.
- **안 B:** 해시 라우팅. 새로고침 안정성과 URL 식별성을 얻지만 게임 상태와 URL 불일치를 막는 가드가 더 필요하다.
- **안 C:** history 라우팅과 `404.html` 복구. 일반 URL은 깔끔하지만 GitHub Pages 배포 복잡성과 직접 진입 오류 위험이 커서 V1에는 비권고한다.

### 15.2 활성 게임 내 도구 표시

- **안 A, 권고:** 넓은 화면은 문맥 패널, 좁은 화면은 단일 도구 메뉴. 장면 몰입과 기능 접근의 균형이 좋다.
- **안 B:** 모든 도구를 항상 노출. 발견성은 높지만 모바일 혼잡과 갤러리 같은 금지 항목의 메뉴 오염 위험이 있다.
- **안 C:** 장면마다 필요한 도구만 노출. 몰입은 높지만 기능 위치가 바뀌어 학습 비용이 커진다.

### 15.3 모바일 주기율표

- **안 A, 권고:** 공간 관계를 보존한 가로 스크롤 표 + 고정되지 않은 상세 패널. 교육 의미를 지키지만 가로 탐색 안내가 필요하다.
- **안 B:** 축소된 전체 표 + 확대. 전체 맥락은 좋지만 작은 셀과 확대 조작의 접근성 위험이 크다.
- **안 C:** 카드 목록만 사용. 읽기는 쉽지만 족·주기 공간 관계를 잃으므로 단독 방식으로는 비권고한다.

### 15.4 호감도 표시

- **안 A:** 정확한 수치와 관계 단계를 함께 표시해 계획성을 높인다.
- **안 B:** 관계 단계만 표시해 서사 몰입을 높인다.
- **표현안 보류:** 정확한 수치 공개 여부는 콘텐츠·UX 결정이 필요하다. 어느 안에서도 유한 최대 게이지를 사용하거나 `80 + 필수 조건`을 호감도만의 성공처럼 표현하지 않는다.

## 17. 승인 상태와 다음 게이트

승인 계약 유지와 QA 재검토를 위해 다음을 확인한다.

- 홈 셸과 활성 게임 셸 분리 및 갤러리 다중 차단 방식 검토
- React + TypeScript + Vite + CSS Modules 및 무라우터 V1 승인 방침 준수
- 세 가지 잠정 반응형 범위와 모바일 주기율표 방식 검토
- Game Systems·State·Narrative·Asset 계약에서 콘텐츠 제안으로 남긴 항목 확인
- `docs/07_UI_UX_SPEC.md`의 승인 구현 결정과 콘텐츠 제안 구분 유지

승인 구현 결정이 반영됐어도 State·Systems 공개 계약과 고위험 흐름의 QA 재검토가 완료되기 전에는 전체가 `Ready to Code`가 아니다.

결정 020·021의 제품 결정 차단은 해제됐지만 상세 화면·콘텐츠·코드 구현은 State·Systems 공개 계약과 고위험 흐름의 QA 재검토 전 자동 승인되지 않는다.
