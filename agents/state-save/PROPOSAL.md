## 1. 제안 요약

하나의 정본 `GameState`와 별도 논리 영역인 `MetaState`를 정의하되, 실제 영속화 시에는 둘을 하나의 저장 루트에 함께 넣는다. 진행 상태는 Day 시작, 필수 시험 제출 직후, 회차 종료 경계에서만 커밋하고, CG 해금과 설정 같은 메타 상태를 중간에 갱신할 때도 저장 루트 안의 게임 상태는 마지막으로 커밋된 Day 스냅샷을 그대로 유지한다.

권고안의 핵심은 다음과 같다.

- 활성 회차는 **단일 자동 저장 슬롯**과 직전 유효본으로 관리한다.
- 기본 Day 스냅샷은 `Day N`의 아침 조회 효과가 실행되기 직전 상태다.
- 실제 도달한 Day 10·20·30의 합격 제출 결과는 되돌릴 수 없도록 제출 직후 같은 Day의 제한적 `examResolved` 체크포인트를 추가한다. 이는 임의 장면 저장이 아니라 필수 시험 결과 전용 경계다.
- Day 종료 결과를 모두 확정한 뒤 다음 Day를 초기화하고, 다음 Day 시작 스냅샷을 원자적으로 커밋한다.
- Day 10·20·30의 고정 문항·순서 계약을 해당 Day 시작 스냅샷에서 확인해 새로고침으로 문항이 바뀌지 않게 한다.
- 시험 완료 없이는 시험 Day를 종료할 수 없고, 50점 미만은 즉시 퇴학 종료로 전이한다.
- 저장은 `localStorage` 이중 버퍼와 활성 포인터를 사용한다. 비활성 버퍼 기록·검증이 끝난 뒤 포인터 한 건만 교체한다.
- 모든 저장은 구조, 의미, 참조, 불변 조건을 검증한다. 실패 시 직전 유효 버퍼로 복구하며 손상값을 임의 보정하지 않는다.
- 마이그레이션은 버전별 순차·순수 변환으로 수행하고, 변환 뒤 전체 검증을 통과해야만 새 버전으로 커밋한다.
- 결정적 복원을 위해 콘텐츠 버전, 회차 시드, 시험 문항·순서 계획, 완료 플래그, 적용 효과 영수증을 저장한다.
- `gender`는 사용자 승인에 따라 선택 구조 없이 고정 리터럴 `male`로 둔다. 이름은 사용자 입력이고 주인공 외형은 유예한다.
- 효과 트랜잭션 완료 직후 Character End 자격을 계산한다. 도달 시험 미완료면 판정을 보류하고 퇴학을 우선하며, 최종 장면 뒤 선택한 결말 하나와 MetaState를 terminal로 원자 커밋한다. terminal 뒤 미래 시험은 실행하지 않는다.
- 시험 중 제한 주기율표 오버레이는 답안·고정 순서·현재 문항을 런타임에서 보존하되 새 저장 경계를 만들지 않는다.

## 2. 제안 상태 타입

### GameState

`GameState`는 한 회차의 규칙상 결과를 복원하는 유일한 정본이다.

| 영역 | 주요 내용 |
|---|---|
| 버전·식별 | `schemaVersion`, `contentVersion`, `runId`, `snapshotRevision`, `checkpoint` |
| 플레이어 | 사용자 입력 이름, 고정 `gender = male` |
| 달력 | Day 1~30, 현재 phase, 점심·방과 후 슬롯 소비 여부 |
| 관계 | 일곱 공략 캐릭터별 정수 호감도 |
| 루트 | 루트 플래그, 완료한 필수 이벤트 ID |
| 미션 | 미션별 상태와 완료 단계 |
| 인벤토리 | 아이템 수량·고유품·미션 예약, 소지금, 1회 구매 이력 |
| 학업 | 공부한 주제, 숙련도 0~3와 마지막 상승 출처, Day 10·20·30 시험 계획·답안·상태·점수 |
| 지식 | 공개된 원소·주기율표·개념 항목 ID |
| 이벤트 | 안정된 이벤트 플래그 ID |
| 중복 방지 | 이미 적용한 효과 트랜잭션 ID |
| 결정성 | 회차 시드와 결정적 난수 스트림 위치 |
| 회차 상태 | 진행 중, 캐릭터 엔드, 노멀 엔드, 퇴학 |

새 게임의 일곱 호감도는 모두 10이다. 호감도는 게임플레이 상·하한이나 clamp 없이 JavaScript 안전 정수만 허용하며, 범위를 넘는 연산은 상태 변경 없이 거부한다. `gender`는 항상 `male`이다. 마스터의 `pending/configurable` 요구는 상충 진술의 임의 해소를 막기 위한 것이었고 사용자 결정으로 해소됐으므로 선택 모드나 호환 계층을 만들지 않는다.

무료 일과 수업은 주제가 `0`일 때만 `1`로 올리고 `1` 이상에서는 복습·진단만 기록한다. 숙련도 `2·3`은 점심·방과 후 슬롯을 소비한 혼자 공부 또는 함께 공부만 만들 수 있으며 미션 보상은 숙련도를 올리지 않는다. 상태는 상승 출처를 검증해 무료 수업이 시험 공부 행동을 대체하지 못하게 하고, 원소 1~20 핵심 사실은 숙련도와 무관하게 기본 조회 대상으로 유지한다. 숙련도는 시험 답안·점수를 자동 보정하지 않는다.

### MetaState

`MetaState`는 회차를 새로 시작하거나 활성 저장을 지워도 유지되는 기기 로컬 진행이다.

| 영역 | 주요 내용 |
|---|---|
| 버전 | `schemaVersion` |
| 갤러리 | 해금 CG ID 집합 |
| 결말 | 확인한 결말 ID 집합 |
| 설정 | 승인된 비음향 선택 설정 |

CG 갤러리 접근 권한은 UI 라우팅 규칙이며 상태값으로 우회 가능하게 만들지 않는다. 음향 설정은 만들지 않는다.

## 3. phase와 Day 전환 제안

일반 Day의 런타임 전이는 다음과 같다.

`morningHomeroom → morningClass → lunchFreeTime → afternoonClass → afterSchoolFreeTime → dayEnd`

- 도달한 Day 10·20·30은 `morningHomeroom → morningClass → lunchFreeTime → afternoonClass → exam → 합격 시 examResolved 커밋`까지 공통이다. 보류 후보가 없으면 `afterSchoolFreeTime → dayEnd`, 있으면 다른 행동 없이 엔딩 후보 흐름으로 간다.
- 시험일 점심 1행동은 시험 전에 사용한다. 50점 이상이면 `examResolved/afterSchoolFreeTime`을 원자 커밋하되, 보류 후보가 없을 때만 방과 후 1행동을 사용한다. 50점 미만이면 다른 phase를 거치지 않고 `terminal(expelled)`로 간다.
- Day 1~29의 `dayEnd`는 당일 효과 확정, 필수 조건 검사, Day 증가, 다음 Day 초기화, 다음 Day 스냅샷 커밋 순으로 처리한다.
- Character End 없이 도달한 Day 30은 합격 후 방과 후와 `dayEnd`를 마치고 Day를 증가시키지 않은 채 노멀 엔드를 확정한다. 방과 후 효과로 자격이 생기면 즉시 Character End 흐름으로 전환한다.
- 저장 가능한 phase는 Day 시작의 `morningHomeroom`, 도달 시험 합격 직후의 `examResolved/afterSchoolFreeTime`, 회차가 끝난 `terminal`뿐이다. 보류 후보가 저장된 `examResolved`는 로드 즉시 엔딩 흐름을 재개한다. 그 밖의 중간 phase는 메모리에만 존재하며 Day 31은 만들지 않는다.
- 새로고침이나 종료로 중간 진행이 사라지면 마지막 Day 체크포인트로 돌아간다. 제출 완료한 시험은 다시 치르지 않는다.
- 효과 트랜잭션 직후 시험 보류 조건이 없고 새 후보가 1명이면 실패 없는 최종 장면으로, 하나의 다인 효과가 만든 새 후보가 2명 이상이면 그 후보만의 단일 선택으로 전환한다. 최종 장면 뒤 정확히 하나의 Character End·메타 해금을 terminal로 원자 커밋한다.

이 시험일 전이는 `docs/05_GAME_SYSTEMS_SPEC.md`와 같은 승인 구현 계약이다.

## 4. 저장·불러오기 제안

### 저장 경계

1. 새 게임 설정 완료 후 Day 1 아침 조회 직전 최초 스냅샷을 만든다.
2. Day 1~29 완료 시 다음 Day 아침 조회 직전 스냅샷으로 교체한다.
3. 도달한 Day 10·20·30 시험 합격 제출 직후 같은 Day의 시스템 강제 `examResolved/afterSchoolFreeTime` 체크포인트를 만든다. 보류 후보가 있으면 방과 후 UI 대신 엔딩 흐름을 재개하며, 이는 사용자 임의 저장 슬롯이 아니다.
4. 퇴학, 캐릭터 엔드, 노멀 엔드 확정 시 종료 스냅샷을 만든다.
5. CG 해금·결말 확인·비음향 설정 변경은 MetaState를 갱신하되, GameState에는 마지막 Day 커밋본만 사용한다.

### 원자적 커밋

브라우저 `localStorage`는 여러 키를 하나의 트랜잭션으로 묶지 못한다. 따라서 다음 이중 버퍼 프로토콜을 사용한다.

1. 현재 활성 버퍼 반대편에 전체 저장 루트를 한 JSON 값으로 기록한다.
2. 즉시 다시 읽어 JSON 파싱, 체크섬, 전체 스키마 검증, 목표 revision을 확인한다.
3. 검증에 성공한 경우에만 활성 포인터 키를 한 번 교체한다.
4. 이전 활성 버퍼는 직전 유효본으로 남긴다.
5. 어느 단계에서든 실패하면 포인터를 바꾸지 않고 이전 유효본을 계속 사용한다.

### 불러오기와 복구

- 활성 포인터가 가리키는 버퍼를 우선 검증한다.
- 실패하면 반대 버퍼를 검증한다.
- 포인터가 없거나 손상됐으면 두 버퍼를 모두 검사해 유효한 것 중 가장 높은 revision을 선택한다.
- 대체 버퍼를 사용했다면 사용자에게 직전 유효 Day로 복구했음을 알리고, 손상 버퍼를 즉시 덮어쓰지 않는다.
- 두 버퍼가 모두 유효하지 않으면 활성 회차 없음으로 안전하게 진입한다. 새 게임 또는 명시적 초기화 전에는 손상 원본을 덮어쓰지 않는다.
- MetaState만 손상되고 GameState가 정상인 경우도 전체 루트를 부분 보정하지 않는다. 직전의 전체 유효 저장 루트로 복구한다.

## 5. 시험 우회와 중복 실행 방지

- Day 10·20·30은 날짜로부터 시험 의무를 계산하며 임의 플래그 하나만 신뢰하지 않는다.
- 시험 Day의 `dayEnd` 진입 조건은 해당 Day 시험의 `completed` 상태와 유효한 0~100 정수 점수다.
- 50점 미만 결과는 동일 상태 전이 안에서 퇴학으로 확정하므로 방과 후·Day 증가·결말 판정으로 진행할 수 없다.
- 해당 시험 Day 시작 시 고정 문항 ID, 문항 순서, 선택지 순서를 검증해 저장한다. 재로드로 새 문제를 뽑을 수 없다.
- 시험 도중에는 저장하지 않는다. 제출 전 종료·재로드는 사용자 관점의 같은 Day 시작과 같은 고정 문항·순서로 돌아가고, 도달 시험의 합격 제출은 즉시 `examResolved/afterSchoolFreeTime`으로 커밋해 점수 재응시·덮어쓰기를 막는다. 보류 후보가 있으면 다른 행동 없이 동일 후보 흐름을 재개하고, 실패 제출은 즉시 terminal로 원자 커밋한다.
- 보상·호감도·아이템·플래그 변경은 안정된 `effectId`를 가진 단일 효과 트랜잭션으로 처리한다. `appliedEffectIds`에 이미 있는 효과는 다시 적용하지 않는다.
- 이벤트 완료 플래그와 필수 이벤트 목록은 ID 집합으로 저장하며, 화면 방문 여부를 완료 근거로 사용하지 않는다.

이 설계는 일반 플레이와 우발적 새로고침에 대한 우회를 막는다. 프런트엔드 전용 `localStorage`는 사용자가 개발자 도구로 값을 조작하는 행위를 보안적으로 막을 수 없으며, 체크섬도 위변조 방지 서명이 아니라 손상 감지 수단이다.

## 6. schemaVersion과 마이그레이션

- 저장 봉투 형식의 `storageFormatVersion`, `GameState.schemaVersion`, `MetaState.schemaVersion`, 콘텐츠 호환성의 `contentVersion`을 구분한다.
- 각 스키마는 양의 정수 버전을 사용한다. 필드 의미·기본값·불변 조건이 바뀌면 버전을 올린다.
- 마이그레이션은 `vN → vN+1` 순서로만 실행하며 원본 객체를 변경하지 않는 결정적 변환이어야 한다.
- 각 단계와 최종 결과를 검증하고, 모두 성공한 뒤에만 현재 버전으로 새 revision을 커밋한다.
- 실패하면 원본과 이전 유효 버퍼를 보존하고 “호환되지 않는 저장”으로 표시한다. 새 게임으로 조용히 대체하지 않는다.
- 미래 버전 저장은 다운그레이드하거나 추측해 읽지 않는다.
- `contentVersion`이 달라도 호환성 표에 명시된 조합만 읽는다. 삭제된 필수 미션·이벤트·시험 문항 ID가 있으면 전용 콘텐츠 마이그레이션 없이는 로드하지 않는다.

향후 구현 대상은 상태 타입, 전이기, 검증기, 저장 어댑터, 마이그레이션과 상태 테스트 파일이다. 정확한 경로는 승인된 React + TypeScript + Vite + CSS Modules 스택 안에서 후속 구현 설계로 확정하며, 검증은 Vitest + React Testing Library, Playwright, axe 계약을 따른다. V1 화면 상태는 URL 라우터의 정본으로 사용하지 않는다.

## 8. 의존성

- **Game Systems:** 승인된 행동·미션·시험·결말 계약을 제공하고 최종 콘텐츠별 조건과 보상 단위를 확정해야 한다.
- **Narrative:** 안정된 장면·이벤트·필수 루트 이벤트·결말 ID와 중복 보상 단위를 제공해야 한다.
- **Frontend UI/UX:** Day 시작 저장 표시, 중간 진행 소실 안내, 복구·비호환·저장 공간 오류 UX, 새 게임 덮어쓰기 확인, 홈 전용 갤러리 접근을 정의해야 한다.
- **Science/Game Systems:** 공부 주제·지식 항목·시험 문항 ID의 정본과 콘텐츠 버전 정책을 제공해야 한다.
- **QA:** 경계 전이, 손상·구버전, 이중 버퍼 장애, 시험 우회, 결정적 복원, 메타 해금 회귀를 재검토해야 한다.
- **PM:** 승인된 시험 phase와 저장 경계를 유지하고 단일 슬롯, 식별자 규약, 콘텐츠 호환성 세부 정책을 검토한다.

`docs/04_NARRATIVE_PLAN.md`, `docs/05_GAME_SYSTEMS_SPEC.md`, `docs/07_UI_UX_SPEC.md`의 승인 구현 결정은 교차 계약으로 사용하고 상세 콘텐츠 제안만 비구속 상태로 둔다. QA 기준과 기존 finding은 `docs/08_QA_PLAN.md`, `agents/qa/REPORT.md`에서 확인했다.

## 9. 가정과 미정 사항

- V1은 활성 회차 한 개를 제공하며 이중 버퍼는 사용자 슬롯 두 개가 아니라 장애 복구용이다.
- 모든 콘텐츠 ID는 릴리스 사이에서 안정적이고 재사용하지 않는다.
- 필수 루트·시험·학습 진행은 무작위성에 의존하지 않는다.
- 연출용 무작위성이 필요하면 저장된 회차 시드에서 이름 있는 스트림으로만 생성한다.
- 저장 시각은 표시·진단용이며 게임 규칙이나 복원 결과 계산에 사용하지 않는다.
- 호감도 무상한 안전 정수, 7단계 미션, 숙련도 `0~3`, 소지금 3,000은 승인된 구현 결정이다. 최종 가격·미션 조건은 콘텐츠 제안이다.
- 주인공 성별은 고정 `male`이며 이름만 사용자 입력이다. 성별 선택값 목록은 없다.
- Character End는 효과 직후 판정·시험 보류·퇴학 우선·정확히 하나의 terminal 커밋을 따른다. 시험 중에는 정본 핵심 사실만 조회하고 검색·필터·비교·힌트·진단은 비활성화한다.

## 10. 잠금 규칙 영향

- 달력 상한 Day 30, Day 기반 저장, 도달한 Day 10·20·30 시험, 50점 미만 즉시 퇴학, 루트 성공 조건, 프런트엔드 전용·무백엔드, `localStorage`, 홈 전용 갤러리 규칙을 유지한다.
- 필수 시험 결과 외의 중간 phase를 저장하지 않아 장면별 자유 저장으로 변질되지 않는다.
- CG 해금을 MetaState로 분리하지만 게임 진행 메뉴에서 갤러리 접근을 허용하지 않는다.
- 사용자 결정으로 성별 모순을 해소하고 상태를 `male`로 단순화하되 주인공 외형은 정의하지 않는다.
- **잠금 영향:** 결정 020의 조기 terminal·미래 시험 미실행은 사용자 승인 예외이고 결정 021은 기존 시험 중 비허용을 대체한다. 추가 변경 요청은 없다.

## 11. 절충과 대안

### 저장 경계

- **승인:** 사용자 관점의 Day 시작 스냅샷과 도달 시험 합격 직후 같은 Day의 제한적 `examResolved/afterSchoolFreeTime` 체크포인트. 보류 후보가 있으면 엔딩 흐름을 즉시 재개하면서 제출 결과 롤백을 막는다.
- **대안:** 완료한 Day의 `dayEnd` 상태 저장. 불러온 뒤 다음 Day 초기화가 다시 실행되어 중복 효과 위험이 커진다.
- **대안:** Day 시작만 저장. 가장 단순하지만 합격 제출 직후 새로고침으로 재응시할 수 있어 Systems의 결과 불가역 제안과 충돌한다.
- **배제:** phase마다 저장. Day 기반 잠금 규칙을 사실상 장면별 저장으로 바꾼다.

### 저장 구조

- **권고:** GameState와 MetaState를 한 저장 루트의 이중 버퍼로 원자적 커밋. 두 영역의 일관성과 복구성이 가장 높다.
- **대안:** 게임과 메타 키를 각각 이중 버퍼링. 독립 복구는 쉽지만 결말·CG 동시 갱신에 교차 키 불일치가 생긴다.
- **대안:** 단일 키 덮어쓰기. 구현은 단순하지만 손상·용량 오류 때 직전 유효본이 없다.

### 슬롯 수

- **권고:** 활성 회차 한 개와 자동 백업. 제품이 요구하지 않은 수동 세이브 슬롯 UX를 추가하지 않는다.
- **대안:** 여러 Day 슬롯. 과거 Day 선택 로드가 시험·선택 되돌리기를 제품 기능으로 확대하므로 별도 PM·QA 결정이 필요하다.

### 브라우저 조작

- **권고:** 구조 검증과 체크섬으로 우발적 손상을 감지하고, 클라이언트 조작 방지는 보장하지 않는다고 명시한다.
- **대안:** 난독화·클라이언트 비밀키. 실질적 보안을 제공하지 않으면서 마이그레이션과 복구만 어렵게 하므로 배제한다.

## 12. QA 위험과 복원 불변 조건

주요 위험:

- 저장 용량 초과 또는 사생활 보호 모드에서 `localStorage` 쓰기 실패
- 버퍼 쓰기 성공 후 포인터 교체 실패, 또는 그 반대의 비정상 종료
- 콘텐츠 ID 삭제·변경으로 정상 JSON이 의미상 무효가 되는 문제
- Day 종료 효과 일부만 적용된 런타임 상태를 실수로 저장하는 문제
- `examResolved`를 임의 중간 저장으로 확대해 Day 기반 규칙을 훼손할 위험
- MetaState 중간 갱신 시 런타임 GameState까지 함께 저장해 Day 규칙을 우회하는 구현 오류
- 탭 두 개가 서로 다른 revision을 저장하는 동시성 충돌
- 매우 긴 `appliedEffectIds` 목록과 저장 용량 증가

필수 복원 불변 조건:

- 같은 유효 스냅샷과 같은 콘텐츠 버전은 같은 Day, phase, 시험 계획, 호감도, 미션, 인벤토리, 지식, 루트·이벤트 상태로 복원된다.
- 기본 Day 스냅샷의 phase는 `morningHomeroom`이며 아직 해당 조회 효과가 적용되지 않았다. 진행 중 예외는 도달 시험의 `examResolved/afterSchoolFreeTime`뿐이고, 보류 후보가 있으면 로드 즉시 엔딩 흐름으로 전환한다.
- Day는 1~30이고 실제 도달한 Day 10·20·30의 미완료 시험을 지나 다음 Day나 결말로 갈 수 없다. Character End 뒤 미래 시험의 미응시는 정상이다.
- 점수 49는 퇴학, 50과 100은 생존이며 0~100 밖 점수는 저장 무효다.
- 모든 공략 캐릭터가 존재하고 새 회차 호감도는 각각 10이다.
- 호감도 80만으로 필수 루트 이벤트를 대체할 수 없다.
- 적용 완료된 `effectId`는 불러오기 후 다시 보상하지 않는다.
- 제출 완료한 시험은 같은 회차에서 재응시하거나 점수를 덮어쓰지 않는다.
- 효과 트랜잭션 완료 뒤 자격을 계산하고 단일 또는 선택한 동시 후보의 실패 없는 최종 장면 뒤 정확히 하나의 terminal Character End를 커밋한다. 선택하지 않은 후보와 미래 시험은 확정하지 않는다.
- 시험 중 제한 주기율표 왕복은 답안·문항·선택지 순서·현재 문항을 보존하고 점수·답안·행동 슬롯을 바꾸지 않는다.
- 손상 복구는 가장 높은 revision이 아니라 **가장 높은 유효 revision**만 선택한다.
- 저장 실패는 기존 유효 저장을 파괴하지 않으며 성공으로 표시되지 않는다.
- 메타 갱신은 마지막 Day 스냅샷보다 최신인 런타임 진행을 영속화하지 않는다.
- `gender`는 새 게임·복원 모두 고정 `male`이며 선택·nullable 상태가 없다.

## 13. 승인 상태와 후속 검토

다음 구현 결정은 승인되어 상세 계약에 반영됐다.

- Day 시작과 Day 10·20·30 `examResolved`의 제한된 스냅샷 경계
- 도달한 Day 10·20·30의 오후 수업 뒤 시험, 합격 후 방과 후 복원, 효과 직후 Character End와 성공 없는 Day 30 노멀 엔드
- 호감도 cap·clamp 없는 JavaScript 안전 정수 검증, 미션 7상태, 시작 재화 3,000과 숙련도 0~3

활성 회차 한 개, 복구용 이중 버퍼, GameState·MetaState 통합 저장 루트, 순차 마이그레이션과 콘텐츠 호환성은 기존 `PROPOSAL`이다. 이 세부안과 최종 콘텐츠 참조는 QA 재검토 전 Ready to Code로 전환하지 않는다.

결정 020의 Character End는 Day 중간 효과 뒤 후보 선택·최종 장면을 거쳐 terminal을 생성하고 이후 일정·시험을 진행하지 않는다. 결정 021의 시험 조회는 시험 phase 안에서 답안·순서·현재 문항을 보존하는 제한 도구 문맥이며 새 체크포인트가 아니다. 이 제품 결정 반영만으로 이중 버퍼 세부·최종 콘텐츠·코드가 자동 승인되지는 않는다.
