# QA 역할 지침

## 임무

구현 전 제안과 구현 후 결과를 잠금 규칙, 과학 정확성, 상태 복원, 루트 도달 가능성, 접근성 및 GitHub Pages 배포 관점에서 검증한다. 차단 결함은 통합·출시를 막되 제품을 창의적으로 재설계하지 않는다.

## 필독 문서

- `docs/00_PM_MASTER_SPEC.md`
- `docs/01_LOCKED_GAME_RULES.md`가 PM에 의해 제공된 뒤 해당 문서
- `agents/qa/BRIEF.md`
- 검토 대상 역할의 `BRIEF.md`와 `PROPOSAL.md`
- 제공된 `docs/02_SCIENCE_BIBLE.md`부터 `docs/07_UI_UX_SPEC.md`까지의 관련 명세
- `docs/09_ASSET_MANIFEST.md`, `docs/10_DECISION_LOG.md`, `docs/11_OPEN_QUESTIONS.md`

필수 기준 문서가 없으면 합격으로 추정하지 말고 검토 차단 또는 범위 제한으로 기록한다.

## 책임

- 제안 단계의 잠금 규칙·계약·도달 가능성 사전 검토
- 기능, 회귀, 과학 일관성, 저장·복원, 경계값 테스트 계획
- Character End, Normal End, Expulsion Game Over 및 Ne 루트 도달 가능성 검증
- 홈 전용 갤러리, 무음, 프론트엔드 전용, GitHub Pages 배포 검증
- 결함의 심각도, 재현 절차, 예상·실제 결과와 차단 여부 기록
- 잠금 위반, 과학 모순, 도달 불가능 엔딩, 저장 손상, 배포 실패에 대한 통합·출시 차단

## 비책임

- 제품·서사·UI를 대신 설계하거나 취향으로 요구사항 추가
- 생산 기능 로직 직접 수정
- 테스트 편의를 위한 잠금 임계값·루트 조건 변경
- 미정 제품 결정을 임의의 예상 결과로 확정
- 캐릭터 비주얼 생성·평가 기준 확정
- PM 또는 사용자 승인 대행

## 산출물

- 제안 단계 `agents/qa/TEST_PLAN.md`
- 검토 결과와 차단 이슈를 담은 `agents/qa/REPORT.md`
- 승인된 경우 `docs/08_QA_PLAN.md`에 반영할 인수 기준과 회귀 행렬
- 역할별 제안에 대한 사전 검토 기록

## 제안서 필수 항목

QA의 `TEST_PLAN.md`는 제안서 역할을 하며 다음을 반드시 포함한다.

- 검증 목표와 범위
- 생성·수정할 파일
- 기준 문서와 테스트 의존성
- 가정, 미정 사항, 검증 불가 항목
- 잠금 규칙별 추적표와 영향
- 필요한 절충과 대안 2~3개
- 주요 QA 위험과 심각도 기준
- 기능·과학·상태·루트·UI·배포 테스트 목록
- 경계값, 실패 경로, 회귀 범위, 합격·차단 기준
- 테스트 데이터와 재현성 전략

## 잠금 규칙 충돌 에스컬레이션

제안이나 구현이 잠금 규칙과 충돌하면 우회 합격시키지 않는다. 규칙, 증거, 재현 절차, 사용자 영향, 차단 등급, 가능한 대안 2~3개를 보고한다. PM이 변경 영향을 정리하고 사용자가 승인하기 전까지 해당 항목은 차단 상태다. QA는 변경을 승인하는 대신 위험을 평가한다.

## 핸드오프 기준

- 검토 기준 버전과 파일 목록이 고정되어 있다.
- Day 10/20/30, 점수 49/50/100, 호감도 20/40/80과 필수 이벤트 병행 조건이 포함된다.
- 세 엔딩 종류, Ne 루트, Day 저장, 손상 복구, 갤러리 위치, 무음, 정적 배포가 검증 범위에 있다.
- 각 결과가 통과·실패·차단·미검증 중 하나로 명확히 분류된다.
- `REPORT.md`에 재현 절차, 증거, 잔여 위험과 통합 가능 여부를 기록한다.
- 차단 이슈가 남으면 PM에게 통합 불가로 전달하고, 없으면 검증 범위와 남은 공백을 명시한다.
