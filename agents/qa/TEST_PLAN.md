## 5. 절충과 대안 검토

아래 대안 비교는 최초 검토의 역사적 근거다. 결정 020·021의 선택안만 실행 예상값으로 사용하며 폐기안은 역사 기록이고 실행하지 않는다.

### 시험일 순서

- 승인안: 일반 수업과 점심 뒤 시험, 합격 후 방과 후와 `dayEnd`. Character End 없이 Day 30을 마치면 노멀 엔드이고 Day 31은 없다.
- 폐기안: 조회 직후 시험 또는 Day 30 시험 직후 결말 직행. 승인 계약의 기대 결과로 사용하지 않는다.

### 시험 제출 저장

- 승인안: Day 시작 기본 저장, 합격 제출은 `examResolved/afterSchoolFreeTime`, 실패 제출은 terminal로 즉시 원자 커밋한다.
- 비승인안: Day 시작만 저장하거나 답안 진행까지 저장하는 방식은 수용 기준이 아니다.

### 호감도 범위

- 승인안: 게임플레이 cap·clamp 없이 JavaScript 안전 정수만 허용하고 범위 밖 연산은 상태 변경 없이 거부한다.
- 폐기안: `-100~100` 제한과 유한 최대 UI 게이지는 수용하지 않는다.

### Character End 판정 시점

- 선택안: 효과 트랜잭션 완료 직후 자격을 판정한다. 도달 시험 미완료 시 합격까지 보류하고 퇴학을 우선하며 terminal 뒤 미래 시험은 실행하지 않는다.
- 폐기안: Day 30 시험 통과 후에만 학기말 Character End를 판정하는 방식은 결정 020으로 대체된 역사적 옵션이며 테스트하지 않는다.

### 시험 중 주기율표

- 선택안: 승인된 기본 사실과 공간 배열·원소 상세만 조회하고 답안·문항 순서·현재 위치·복귀 포커스를 보존한다. 검색·필터·비교·힌트·오답 진단과 자동 정답·점수 보정은 금지한다.
- 폐기안: 시험 중 주기율표를 전면 비허용하는 방식은 결정 021로 대체된 역사적 옵션이며 테스트하지 않는다.

## 6. 테스트 데이터와 재현성

- `new-run`: Day 1, 일곱 호감도 10, 빈 루트 진행, 승인 초기 지식.
- `aff-boundary`: 각 캐릭터에 -1, 0, 9, 10, 19, 20, 39, 40, 79, 80 값을 독립 주입한 유효 후보 상태.
- `exam-day-10/20/30`: 해당 시험 미완료 Day 시작 상태.
- `exam-score`: 판정 계층 직접값 49, 50, 100과 실제 10문항 기준 4·5·10개 정답.
- `ending-immediate`: Day 1~30 중 한 행동 전에는 미자격, 같은 행동 결과로 한 명 또는 복수 자격이 성립하는 후보 상태.
- `ending-normal-none`: Day 30 시험 합격 후 방과 후와 `dayEnd`까지 자격 후보가 없는 상태.
- `learning-0/1/2/3`: 일곱 주제별 숙련도와 마지막 상승 출처, 남은 행동 슬롯을 조합한 상태.
- `na-invitation`: 일반 거절, 일정 충돌, 사전 고지 정중한 불참, 약속 파기, 책임 전가, 수락 후 무책임 이탈의 독립 선택 결과.
- `route-{h,c,o,f,na,cl,ne}-minimum`: 승인된 최소 성공 경로의 `earliestCompletionDay`, 도달 시험 제출·합격 여부, Day/phase별 행동·보상 추적표.
- `ne-farm-only`: 일반 대화·선물의 모든 유일 보상을 얻었으나 특수 조건은 없는 상태.
- `save-valid/corrupt/stale/future`: 정상, 잘린 JSON, 체크섬 오류, 누락 필드, 구버전, 미래 버전.
- `gallery-locked/unlocked`: CG 미해금·해금 MetaState와 활성 GameState 조합.

필수 조건과 문항은 고정 ID를 사용한다. 난수가 허용된 연출은 저장된 시드와 스트림 커서를 기록한다. 모든 E2E는 시작 fixture, 빌드·콘텐츠·스키마 버전, 브라우저를 기록한다.

## 16. 합격·차단 기준

- 설계 합격: CON-01~10이 모두 `PASS`, 루트별 예산표와 `earliestCompletionDay`·도달 시험 합격 추적표가 제출되고 정적 도달성 검사가 통과하며 결정 로그가 갱신되어야 한다.
- 기능 합격: 관련 테스트 100% 통과, 재현 가능한 Critical·High 결함 0건이어야 한다.
- 출시 합격: 마스터 최소 수용 행렬 전체와 P0 회귀 100% 통과, Pages 실배포 검증 완료가 필요하다.
- 즉시 차단: 잠금 위반, 과학 모순, 필수 시험 우회, 49/50 역전, 도달 불가능 엔딩, 저장 파괴·비결정 복원, 홈 외 갤러리, Pages 실패.

재검토 결과 CON-01~10은 최신 결정 상태를 서로 동일하게 반영했다는 문서 기준으로 `PASS`다. CON-07·09는 결정 020·021의 선택된 기대 결과가 단일 계약으로 정렬되고 폐기 옵션이 역사·비실행으로 구분됐음을 뜻한다. 실제 기능 실행은 구현 전 `NOT TESTED`다.

OQ-002·003의 제품 결정 차단은 해제됐다. 승인 계약은 PM의 Slice별 코드 승인 기준선으로 사용할 수 있지만 QA가 Slice 또는 전체 구현을 자동 승인하지 않는다. 코드·최종 콘텐츠·자산·접근성·production build·실배포가 필요한 검사는 계속 `NOT TESTED`이며 구현 시 `END-I-*`, `END-N-*`, `EXM-P-*`, `RTE-13~14`를 P0로 실행한다.
