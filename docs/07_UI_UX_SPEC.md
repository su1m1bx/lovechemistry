# UI/UX 명세

**상태:** `APPROVED IMPLEMENTATION DECISION 반영 / 콘텐츠 상세는 PROPOSAL`  
**버전:** 0.3  
**작성일:** 2026-09-03  
**구현 승인:** 결정 020의 즉시 Character End와 결정 021의 시험 중 제한 기본 조회 계약 반영. 상세 콘텐츠·비주얼·코드는 자동 승인되지 않음  
**비주얼 확정:** 없음

## 1. 목적과 적용 범위

이 문서는 《러브 앤 케미스트리》의 정보 구조, 화면 흐름, VN 표현, 반응형 동작, 접근성 및 각 게임 도구의 사용자 경험 계약을 정의한다. 승인된 구현 결정은 구속력 있는 계약이고, 비주얼·상세 콘텐츠·미정 UI 표현은 계속 `PROPOSAL`이다.

`docs/04_NARRATIVE_PLAN.md`, `docs/05_GAME_SYSTEMS_SPEC.md`, `docs/06_STATE_SAVE_SCHEMA.md`의 승인 구현 결정을 교차 계약으로 소비한다. 각 문서에서 `PROPOSAL`로 표시한 상세 콘텐츠는 UI가 임의로 확정하지 않는다.

이 문서가 정하는 것은 화면의 책임, 정보 우선순위, 전이 조건의 소비 방식과 검증 가능한 동작이다. 다음은 정하지 않는다.

- 색상, 서체, 아이콘 스타일, 장식 표현과 최종 시각 언어
- 캐릭터 외형, 표정 시트, CG 구도, 이미지 생성 프롬프트
- 자산의 정확한 픽셀 크기와 종횡비
- 행동 비용, 호감도 증감량, 미션·루트 조건, 문항 수와 같은 게임 규칙
- `GameState`·`MetaState`의 정확한 타입과 저장 구현

충돌 우선순위는 `docs/00_PM_MASTER_SPEC.md`, `docs/01_LOCKED_GAME_RULES.md`, 관련 승인 계약, 본 문서 순이다.

## 2. UX 목표

1. 플레이어가 언제나 현재 Day와 페이즈, 지금 가능한 행동, 행동의 잠금 이유를 이해한다.
2. VN의 관계 경험과 공부·미션·장소 선택이 하나의 학교생활 흐름으로 이어진다.
3. 주기율표에서 배운 사실을 미션·대화·시험 판단에 다시 사용할 수 있다.
4. 모바일과 데스크톱에서 정보 손실 없이 같은 핵심 기능을 완료할 수 있다.
5. 키보드, 터치, 확대, 화면 낭독기, 모션 감소 환경에서 진행 불가 상태가 생기지 않는다.
6. 홈 전용 CG 갤러리 규칙을 내비게이션과 상태 전이 양쪽에서 보장한다.
7. 자산과 세부 비주얼이 미정이어도 외형 중립 플레이스홀더로 구조와 기능을 검증할 수 있다.

## 3. 애플리케이션 영역

### 3.1 홈 셸

홈 셸은 활성 플레이 밖의 시작·복귀·메타 기능 영역이다.

- 타이틀
- 새 게임 및 플레이어 설정
- 불러오기
- CG 갤러리
- 표시·접근성 설정(필요한 경우)

음향이 없으므로 음량, 음소거, BGM, 음성 설정은 존재하지 않는다.

### 3.2 활성 게임 셸

활성 게임 셸은 한 회차 안에서 사용하는 영역이다.

- Day 전환과 하루 요약
- VN 장면
- 점심 자유시간과 방과 후 자유활동
- 장소·이벤트
- 공부와 함께 공부
- 주기율표
- 미션
- 인벤토리
- 버튼형 매점

활성 게임 셸은 CG 갤러리 화면, 링크, 메뉴 항목을 포함하지 않는다.

### 3.3 강제 진행·종료 영역

- Day 10·20·30 시험
- 시험 결과
- 퇴학 게임 오버
- 캐릭터 엔딩
- 노멀 엔딩

이 영역에서는 상태 계약이 허용하지 않는 일반 메뉴 이동, 불러오기, 자유시간 이동을 노출하지 않는다.

## 5. 내비게이션 계약

### 5.1 화면별 접근 가능 영역

| 출발 문맥 | 허용 대상 | 금지 대상 |
|---|---|---|
| 타이틀 | 새 게임, 불러오기, CG 갤러리, 표시·접근성 설정 | 활성 장면 직접 진입 |
| 새 게임 | 타이틀 복귀, 계약된 플레이어 설정, 시작 확인 | CG 갤러리로 횡이동 |
| 불러오기 | 타이틀 복귀, 유효한 Day 스냅샷 복원 | 임의 장면 선택 |
| CG 갤러리 | CG 목록·상세, 타이틀 복귀 | 활성 게임 셸 진입 |
| 일반 활성 게임 | 현재 허용 행동, 주기율표, 미션, 인벤토리, 버튼형 매점 | CG 갤러리 |
| 시험 | 현재 문항, 문항 검토, 제출, 제한된 기본 주기율표 오버레이 | 일반 게임 메뉴, 불러오기, CG 갤러리, 검색·필터·비교·힌트·오답 진단 |
| 퇴학·엔딩 | 결과 확인, 계약된 타이틀 복귀 | 종료된 회차의 임의 재개, CG 갤러리 직접 열기 |

### 5.2 전역 문맥

활성 게임 화면은 다음 정보를 일관된 위치 또는 일관된 접근 경로로 제공한다.

- `DAY NN / 30`
- 현재 페이즈
- 현재 장소(장소 개념이 있는 화면)
- 진행 중인 강제 흐름 여부
- 사용 가능한 도구 메뉴

정확한 행동 기회 수나 비용은 Systems가 제공할 때만 표시한다. 없는 값을 UI가 추측하거나 무한 행동처럼 표현하지 않는다.

### 5.3 뒤로 가기와 이탈

- 브라우저 뒤로 가기를 게임 상태 되감기로 사용하지 않는다.
- 선택 확정 전에는 계약이 허용하는 범위에서 이전 화면으로 돌아갈 수 있다.
- 시간·아이템·재화·관계 상태를 소비한 뒤에는 단순 뒤로 가기로 취소하지 않는다.
- 귀가, 시험 제출, 저장 데이터 삭제처럼 영향이 큰 동작은 결과를 설명하고 확인을 받는다.
- 확인 대화상자는 취소를 기본 안전 경로로 제공하되, 시험 등 필수 흐름 자체를 회피하게 만들지 않는다.

## 6. 핵심 사용자 흐름

### 6.1 새 게임

```text
타이틀 → 새 게임 → 이름 입력·검증 → 남성 주인공 안내 → 시작 정보 확인 → Day 1 전환
```

- 이름 입력은 비어 있음, 허용 길이 초과, 공백만 입력을 명확히 검증한다. 정확한 길이와 문자 정책은 State·Narrative 계약에 의존한다.
- 주인공은 사용자 결정으로 남성 고정이며 성별 선택 컨트롤을 제공하지 않는다. 이름만 사용자 입력으로 받는다. 남성 안내에 미승인 외형·신체·복장 정보를 넣지 않는다.
- 시작 확인에서 30일 구조와 날짜 기반 저장의 핵심만 간결하게 알린다.

### 6.2 불러오기

```text
타이틀 → 불러오기 → 저장 경계 확인 → 유효성 확인 → Day 시작, 시험 합격 후 방과 후 또는 보류된 엔딩 후보 흐름 복원
```

- 저장 요약은 Day, 저장 시각, 식별 가능한 진행 문맥을 상태 계약이 제공하는 범위에서 표시한다.
- 장면 단위 저장처럼 보이는 UI를 만들지 않는다.
- 저장 없음, 손상, 구버전·이관 가능, 복구 불가를 서로 다른 상태로 설명한다.
- V1은 단일 활성 회차와 내부 이중 버퍼를 사용한다. 사용자 관점에는 Day 시작 스냅샷을 기본으로 표시하고, 시험 합격 뒤에는 같은 Day `examResolved` 시스템 강제 체크포인트임을 구분한다. 보류 후보가 없으면 방과 후로, 있으면 동일 엔딩 후보 흐름으로 즉시 복원한다. 내부 버퍼와 체크포인트는 사용자 선택 저장 슬롯으로 노출하지 않는다.

### 6.3 일반 Day

```text
Day 전환
→ 아침 조회
→ 오전 수업
→ 점심 자유시간
→ 오후 수업
→ 방과 후 자유활동
→ 귀가·하루 종료
→ 하루 요약 / Day 스냅샷 경계
→ 다음 Day
```

각 페이즈 종료는 State·Systems 명령의 성공 응답을 받은 뒤 화면에 반영한다. UI가 페이즈를 자체 계산하지 않는다.

### 6.4 시험

```text
시험 안내 → 문항 응답 → 제출 전 검토 → 제출 확인 → 채점 결과
├─ 50~100점, 보류 후보 없음: 결과 원자 커밋 → 같은 Day 방과 후
├─ 50~100점, 보류 후보 있음: 결과 원자 커밋 → 즉시 엔딩 후보 흐름
└─ 0~49점: 즉시 퇴학 GAME OVER
```

활성 회차가 도달한 Day 10, 20, 30 시험을 저장·내비게이션으로 건너뛸 수 없어야 하며 Character End 뒤 미래 시험은 표시하지 않는다.
제출 전 종료는 같은 Day 시작과 같은 고정 문항·순서로 복원하고, 실패 제출은 terminal로 즉시 원자 커밋한다.

### 6.5 즉시 Character End와 Day 30 종료

```text
Day 30 아침 조회 → 오전 수업 → 점심 자유시간 → 오후 수업 → 시험
├─ 0~49점: 즉시 퇴학 GAME OVER
└─ 50~100점: 방과 후 자유시간 → dayEnd
   └─ Character End 후보 없이 dayEnd 완료: 노멀 엔딩
```

호감도 80 이상만으로 성공 표시를 만들지 않는다. 필수 미션·이벤트와 결말 조건 판정 결과를 함께 소비한다.
효과 트랜잭션 완료 직후 자격을 계산한다. 현재 시험 또는 이미 도달한 필수 시험이 미완료면 자격 UI를 보류하고 시험으로 복귀시키며, 50점 미만이면 후보보다 퇴학 화면을 우선한다. 후보 1명은 실패 없는 최종 장면 뒤 Character End 저장 결과를 표시한다. 하나의 다인 이벤트로 2명 이상이 동시에 자격을 얻으면 그 후보만 즉시 보여 한 명을 선택하게 하고, 선택 뒤에는 결과를 뒤집는 선택을 제공하지 않는다. 성공 회차는 Day 30 전에 끝나며 이후 미래 시험·Day 화면을 표시하지 않는다. 노멀 엔드는 Character End 없이 Day 30 시험 합격 후 방과 후와 `dayEnd`를 마친 경우이고 Day 31은 없다.

## 7. 화면 명세

### 7.1 타이틀

**목적:** 새 회차 시작, 날짜 저장 복원, 홈 전용 갤러리 접근의 유일한 허브다.

**필수 요소:**

- 제품 제목
- 새 게임
- 불러오기
- CG 갤러리
- 필요한 표시·접근성 설정
- 저장 또는 초기화 오류 알림 영역

**상태:** 유효한 저장이 없으면 불러오기를 비활성화하고 이유를 텍스트로 제공한다.

### 7.2 플레이어 설정

**목적:** 사용자 입력이 필요한 플레이어 정보만 받는다.

**필수 요소:** 이름 입력, 오류 설명, 남성 주인공 고정 안내, 시작 확인, 취소. 성별 선택 UI는 없다.

### 7.3 Day 전환·하루 요약

**목적:** 날짜와 하루 경계를 분명히 하고 날짜 기반 저장 기대를 맞춘다.

**필수 요소:** `DAY NN / 30`, 완료한 주요 행동, 학습·미션 변화, 시험 예정 알림, 저장 결과. Character End가 먼저 확정되면 이후 날짜를 예고하지 않는다. Character End 없이 도달한 Day 30 `dayEnd`는 다음 Day 저장이 아니라 노멀 엔드로 이어짐을 표시한다.

**금지:** 저장 성공 전에 성공한 것처럼 표시, 다음 시험을 임의로 연기, 자유 장면 저장 제공.

### 7.4 자유시간 선택

**목적:** 점심 1회 또는 방과 후 1회의 가능한 행동을 비교하고 하나를 의도적으로 선택하게 한다. 시험일 방과 후는 합격 결과가 원자 커밋된 뒤에만 연다.

**필수 요소:** 현재 페이즈, 행동·장소 목록, 비용 또는 선택 기회, 잠금 이유, 관련 미션·인물 힌트의 승인된 수준, 선택 확인.

**금지:** 같은 날 모든 행동이 가능한 것처럼 표현, 잠긴 행동을 설명 없이 숨김, UI 자체의 비용 계산.

### 7.5 학교 장소·이벤트

**목적:** 기본 학교 공간에서 인물, 미션, 사건과 상호작용한다.

**기본 장소:** 교실, 교문, 특별교실·과학실, 운동장, 복도, 계단, 옥상.

추가 장소는 UI가 임의 생성하지 않는다. 장소 선택은 일러스트 지도 없이도 작동해야 하며, 지도 사용 여부는 비주얼 확정이 아니다.

### 7.6 VN 대화

**목적:** 서사, 관계, 학습과 선택을 같은 장면 문맥에서 전달한다.

**필수 계층:**

1. 배경 또는 배경 플레이스홀더
2. 반신 캐릭터 또는 외형 중립 플레이스홀더
3. Day·페이즈·장소 문맥
4. 화자명과 대화 본문
5. 선택지 또는 계속 동작
6. 허용된 보조 도구

**동작 계약:**

- 화자명과 본문은 보조 기술이 구분할 수 있는 구조를 사용한다.
- 선택지는 버튼 또는 적합한 입력 그룹이며 화면 순서와 키보드 순서를 일치시킨다.
- 비활성 선택지는 가능하면 이유를 제공하되 숨겨진 루트 조건은 누설하지 않는다.
- 선택 확정 뒤 관계·아이템·플래그 효과를 UI가 재계산하지 않고 Systems 결과를 표시한다.
- 대화 기록이 승인되면 텍스트와 화자 중심으로 제공한다. 갤러리 기능과 결합하지 않는다.
- 자동 재생, 음성 재생, 음량 설정은 제공하지 않는다.

**레이아웃:**

- 데스크톱은 장면 안전 영역과 읽기 폭을 보존하고 대화 영역을 안정적으로 유지한다.
- 모바일은 이미지보다 본문과 선택지의 읽기·조작을 우선한다.
- 낮은 화면에서는 본문과 선택지를 각각 읽을 수 있게 스크롤 영역을 관리하되 중첩 스크롤을 최소화한다.
- 정확한 스프라이트 크기·위치·종횡비는 Asset Integration 승인 전 확정하지 않는다.

### 7.7 공부

**목적:** 승인된 화학 주제를 선택해 게임 행동에 쓰일 지식을 익힌다.

**필수 요소:**

- 주제명과 간단한 학습 목표
- 현재 숙련도 `0~3`, 이번 학습의 출처와 다음 단계 효과
- 선행 조건과 잠금 이유
- Systems가 제공하는 시간·행동 비용
- 시험·대화·미션 활용처의 승인된 안내
- 혼자 공부 또는 함께 공부 가능한 경로

무료 일과 수업은 주제가 `0`일 때만 `1`로 올리고 `1` 이상에서는 복습·진단으로 표시한다. 숙련도 `2·3` 버튼은 점심·방과 후의 혼자 공부 또는 함께 공부처럼 행동 슬롯을 소비하는 경로에서만 제공하며, 예상 비용을 확정 전에 표시한다. 시험 공부 행동은 무료 수업으로 대체됐다고 표시하지 않는다.

단계 효과는 `1 = 시험 범위 체크리스트·기초 오답 진단·족/주기 필터`, `2 = 대화 해석 단서·미션 비정답형 힌트·두 원소 비교`, `3 = 복합 비교·범위 내 심화 오답 설명·일부 더 나은 해결/대화 선택의 이해 또는 해금`으로 설명한다. 숙련도가 시험 점수를 올리거나 정답을 대신 선택한다고 표현하지 않는다.

함께 공부는 캐릭터 선택 후 곧바로 수치 보너스만 주는 화면이 아니라 캐릭터 음성과 상호작용을 보존한 VN 장면으로 이어진다. O는 강한 중심축이지만 기능은 O 전용으로 만들지 않는다.

완료 화면은 새로 공개·강화된 지식과 영향 영역을 설명하되 호감도나 학습 효과를 UI가 독립 판정하지 않는다.

### 7.8 주기율표

**목적:** 원소 1~20을 조회·비교하고 미션·대화·공부 판단에 활용한다.

**표 구조:**

- 원소의 실제 족·주기 위치 관계를 보존한다.
- 원자번호 1~20만 대화식 학습 대상으로 제공한다.
- 범위 밖 위치는 빈 구조 또는 비대화식 표식으로 구분하고 학습 대상처럼 보이지 않게 설명한다.
- 각 대화식 셀의 접근 가능한 이름은 최소 원자번호, 원소명, 기호를 포함한다.

**상세 정보:**

- 원자번호
- 원소 기호
- 한국어명과 보조 영문명
- 족과 주기
- 전자껍질별 전자배치
- 승인된 원자가전자 정보
- 숙련도와 단계별 활용 도구 상태

모든 사실은 단일 원소 정본에서 읽는다. 캐릭터 성격이나 관계 모티프는 과학 상세와 명확히 분리한다.

**도구:** 일반 플레이에서는 이름·기호·원자번호 검색을 기본 제공한다. 족·주기 필터는 숙련도 1, 두 원소 비교는 2, 복합 비교는 3의 Systems 결과를 소비한다. 검색 결과가 없어도 필터 해제와 전체 표 복귀가 가능해야 한다. 원소 1~20 핵심 사실 자체는 숙련도와 무관하게 기본 조회한다.

**문맥 복귀:** 미션·공부·대화에서 열었으면 원래 문맥을 표시하고 안전하게 돌아간다. 시험에서는 답안·문항 순서·현재 문항 위치를 보존하는 오버레이·도구 화면으로 열고, 닫으면 호출한 동일 문항과 조작 요소로 포커스를 돌린다. 시험 문맥에는 기본 공간 배열과 원소 1~20의 정본 핵심 사실 상세만 표시하며 검색, 숙련도 기반 족·주기 필터, 두 원소 비교, 복합 비교, 미션·대화 힌트, 오답 진단을 숨기거나 명확히 비활성화한다. 조회는 행동 비용이 없고 답을 자동 선택하거나 점수를 보정하지 않는다.

**모바일:** 표의 공간 관계를 카드 목록으로 완전히 대체하지 않는다. 가로 스크롤 표와 별도 상세 영역을 제공하고, 키보드와 화면 낭독기에는 논리적인 행·열 또는 동등한 관계 정보를 제공한다.

### 7.9 미션

**목적:** 캐릭터 요청, 단서, 필요한 행동과 진행 결과를 추적한다.

**목록 정보:** 요청자, 목적, 진행 상태, 실제로 존재하는 경우 기한, 완료 가능 알림. 상태는 `locked`, `available`, `active`, `readyToTurnIn`, `completed`, `failed`, `expired` 일곱 개를 손실 없이 표시한다.

**상세 정보:** 요청 내용, 발견한 단서, 관련 장소·아이템·학습 주제, 다음에 할 수 있는 행동. 미발견 조건과 정답은 노출하지 않는다.

**상호 이동:** 관련 주기율표, 공부, 장소, 인벤토리로 이동한 뒤 미션 문맥으로 복귀할 수 있다.

Ne 관련 숨겨진 조건은 발견 전 빈 슬롯, 잠긴 미션, 갤러리 설명으로 존재를 누설하지 않는다.

### 7.10 인벤토리

**목적:** 선물, 미션 물건, 학교생활 물건, 필요한 공부 물건을 단순하게 관리한다.

**필수 요소:** 항목명, 수량, 분류, 설명, 현재 사용 가능 여부와 불가 이유.

**동작:** 선택, 상세 확인, 계약된 문맥에서 사용 또는 전달. 소비·효과는 Systems 응답 후 갱신한다.

**금지:** 장비 슬롯, 전투 능력치, 복잡한 희귀도·강화 구조.

### 7.11 매점

**목적:** 상품 구매와 미션·선물 관련 물품 획득을 지원한다.

- 학교 장소 목록이나 지도 노드로 제공하지 않는다.
- 활성 게임 셸의 명시적인 `매점` 버튼 또는 도구 메뉴로 연다.
- 상품명, 가격·재화, 보유 수량, 구매 가능 여부, 불가 이유를 표시한다.
- 구매 수량과 총비용을 확인하고 중복 제출을 막는다.
- 구매 성공 후 잔액과 인벤토리 변화는 Systems 결과로 갱신한다.
- 미션 정답이나 캐릭터 선호를 승인 없이 자동 표기하지 않는다.

### 7.12 시험

**시험 안내:** 해당 Day, 평가 범위, 고정 10문항·문항당 10점, 진행·제출 방식, `50점 미만 즉시 퇴학`, 행동 비용 없는 제한 주기율표 조회 범위를 시작 전에 알린다.

**문항 화면:** 한 화면 한 문항을 기본 제안으로 하며 문항 번호, 전체 문항 수, 답변 상태, 이전·다음, 제출 검토를 제공한다. 정확한 문항 유형은 Science·Systems 계약을 따른다.

**제출 검토:** 미응답 문항을 식별하고 이동할 수 있다. 필수 시험 자체를 취소하거나 일반 게임으로 돌아가는 동작은 없다.

**결과:** 100점 만점 점수, 50점 기준 판정, 문항별 승인 해설. 정답·오답은 색 이외의 텍스트와 아이콘으로도 구분한다.

**경계 수용 기준:** `49 → 퇴학`, `50 → 생존`, `100 → 생존`.

시간 제한은 현재 규칙에 없으므로 넣지 않는다.

제출 전 종료·새로고침 시 사용자 관점의 해당 Day 시작으로 돌아가며 같은 고정 문항과 순서를 유지한다고 제출 확인 전에 알린다. 합격 제출 뒤에는 같은 Day 방과 후의 시스템 강제 체크포인트로, 실패 제출 뒤에는 terminal로 복원된다. 이를 사용자 임의 저장 슬롯이나 장면 저장으로 표시하지 않는다.

### 7.13 결과·퇴학·엔딩

- 퇴학 화면은 시험 점수와 50점 기준을 명확히 연결하고 `GAME OVER`와 타이틀 복귀를 제공한다.
- 캐릭터 엔딩은 상태가 확정한 성공 루트와 관련 CG 해금 결과를 표시한다.
- 노멀 엔딩을 실패 오류처럼 표현하지 않고 유효한 결말로 제공한다.
- CG가 해금되어도 활성 흐름에서 갤러리를 직접 열지 않는다. `타이틀의 갤러리에서 확인 가능` 알림만 제공할 수 있다.
- 단일 후보는 최종 캐릭터 장면을 즉시 시작하고, 하나의 다인 이벤트로 생긴 복수 후보는 자격 후보만 표시하는 강제 선택 화면을 먼저 제공한다. 선택 후 최종 장면에는 숨은 실패·재판정을 두지 않으며 종료 저장 성공·실패를 거짓으로 표시하지 않는다.
- Character End terminal에는 선택한 캐릭터 하나와 해금 결과만 표시하고 미래 시험이나 계속하기를 제공하지 않는다.

### 7.14 호감도 표시

- 호감도 값은 JavaScript 안전 정수로 표시하며 게임플레이 상·하한이나 clamp를 암시하지 않는다.
- `100`을 최대치로 둔 진행 막대, 백분율, 가득 참 상태처럼 유한 최대를 전제하는 게이지를 사용하지 않는다.
- 정확한 수치를 공개하는 경우 현재 값과 `<0`, `20`, `40`, `80` 관계 기준을 텍스트로 제공한다. 단계만 공개하는 콘텐츠안도 임계값과 필수 조건을 왜곡해서는 안 된다.
- 큰 양수·음수에서도 레이아웃이 깨지지 않아야 하며 `80 이상`을 호감도만의 엔딩 확정으로 표시하지 않는다.

### 7.15 CG 갤러리

**접근:** 타이틀에서만 진입한다.

**목록:** 해금 CG는 승인된 썸네일과 연관 정보를 표시한다. 미해금 CG는 비스포일러 플레이스홀더와 `미해금` 상태만 표시하고, 캐릭터·이벤트·조건을 추측하게 하는 정보를 제한한다.

**상세:** 해금된 CG만 연다. 이전·다음 탐색은 해금 항목 범위에서만 제공한다.

**상태:** `MetaState`의 해금 정보를 읽고 활성 `GameState`를 수정하지 않는다.

## 8. 홈 전용 갤러리 보장 계약

갤러리 접근 제한은 다음 네 층으로 검증한다.

1. **정보 구조:** 갤러리는 `HomeShell` 하위에만 존재한다. 종료 상태라는 이유만으로 홈 문맥으로 간주하지 않는다.
2. **내비게이션:** `GameShell`, 시험, 결과·엔딩 메뉴에는 갤러리 트리거가 없다.
3. **전이 가드:** 활성 게임 또는 종료 결과 흐름이면 갤러리 전이 요청을 거부하고 현재 문맥을 유지한다. `runStatus` 하나만으로 허용 여부를 판정하지 않는다.
4. **데이터 경계:** 갤러리는 메타 해금만 읽고 활성 회차의 날짜·관계·미션 상태를 변경하지 않는다.

주소 변조, 브라우저 기록, 개발 중 남은 링크, 엔딩 직후 해금 알림으로도 활성 게임에서 갤러리가 렌더링되지 않아야 한다. 정확한 판별 필드는 State 계약 후 연결한다.

## 9. 반응형 동작

### 9.1 잠정 범위

| 모드 | 제안 기준 | 레이아웃 동작 |
|---|---:|---|
| 소형 | `0~767px` | 단일 열, 전폭 본문·상세, 보조 도구 접기, 주기율표 가로 탐색 |
| 중형 | `768~1023px` | 주 콘텐츠와 선택적 보조 패널, 필요시 패널 전환 |
| 대형 | `1024px 이상` | 주 콘텐츠와 문맥 패널 병렬, 읽기 폭과 장면 안전 영역 제한 |

이 수치는 구현 승인 대상의 잠정 기준이며 자산 비율을 확정하지 않는다. 구성요소는 컨테이너 폭과 콘텐츠 길이에도 적응해야 한다.

### 9.2 공통 규칙

- 세로 모바일을 완전 지원하고 가로 모바일의 낮은 높이에서도 진행 버튼에 접근할 수 있어야 한다.
- `200%` 확대에서 핵심 정보와 동작이 잘리거나 겹치지 않는다.
- 고정 높이에 긴 대사·선택지·설명을 가두지 않는다.
- 호버 전용 정보와 정밀 포인터를 요구하는 동작을 사용하지 않는다.
- 모바일 주요 터치 대상은 권장 `44×44 CSS px` 수준을 목표로 한다.
- 안전 영역이 있는 기기에서 상·하단 조작부가 가려지지 않는다.

### 9.3 화면별 재배치

| 화면 | 대형 | 소형 |
|---|---|---|
| VN | 장면 중심 + 안정된 하단 대화 + 선택적 보조 패널 | 대화·선택 우선 단일 열, 보조 메뉴 접기 |
| 자유시간 | 행동 목록과 상세 병렬 가능 | 목록 선택 후 상세 전환 또는 시트 |
| 공부 | 주제 목록 + 상세·캐릭터 선택 | 단계식 단일 열 |
| 주기율표 | 표 + 상세 패널 병렬 | 가로 스크롤 표 + 아래 상세 |
| 미션 | 목록 + 상세 | 목록에서 상세로 전환, 문맥 복귀 제공 |
| 인벤토리·매점 | 목록/격자 + 상세 | 읽기 가능한 목록 우선, 상세 전환 |
| 시험 | 중앙 문항 + 진행 현황 | 문항 우선, 진행 현황 축약·접기 |
| 갤러리 | 목록 + 해금 상세 | 단일 열 또는 폭 적응 목록, 스포일러 차단 동일 |

## 10. 접근성 요구사항

### 10.1 기준

WCAG 2.2 AA 충족을 목표로 하며 자동 검사만으로 완료 판정하지 않는다.

### 10.2 키보드와 포커스

- 모든 대화 진행, 선택, 필터, 구매, 제출, 닫기 기능은 키보드로 수행할 수 있다.
- 포커스 표시를 제거하지 않는다.
- 화면 전환 후 포커스를 새 화면 제목 또는 작업 시작점으로 이동한다.
- 모달·시트는 포커스를 내부에 유지하고 닫으면 호출한 요소로 돌려보낸다.
- 주기율표 셀은 예측 가능한 순서로 이동하며 스크롤 때문에 포커스가 사라지지 않는다.
- 비활성 요소는 이유를 인접 설명 또는 접근 가능한 설명으로 제공한다.

### 10.3 의미 구조와 낭독

- 화면당 식별 가능한 주 제목을 제공한다.
- 대화 화자, 본문, 선택지를 의미적으로 구분한다.
- 시험 답안은 적합한 라디오·체크 그룹을 사용하고 그룹 질문을 연결한다.
- 표 형태의 주기율표는 족·주기 관계를 보조 기술이 이해할 수 있는 구조 또는 동등한 설명으로 제공한다.
- 실시간 알림은 구매·저장 오류처럼 필요한 변화에만 사용하고 대사를 중복 낭독하지 않는다.

### 10.4 시각 정보

- 텍스트와 필수 UI는 AA 명도 대비를 충족한다.
- 잠금, 완료, 오류, 정답, 관계 상태를 색상만으로 구분하지 않는다.
- 텍스트를 이미지로 만들지 않는다.
- 브라우저 텍스트 확대와 사용자 글꼴 설정에서 내용이 손실되지 않는다.
- 최종 색상·서체는 현재 확정하지 않으며 비주얼 단계에서 별도 대비 검증한다.

### 10.5 모션과 자산

- `prefers-reduced-motion`에서 불필요한 전환을 제거하고 필수 변화는 즉시 완료한다.
- 장식용 스프라이트는 빈 대체 텍스트를 사용한다.
- 정보성 CG의 대체 설명은 Narrative·Asset Integration이 스포일러 수준과 함께 승인한다.
- 미해금 CG의 대체 텍스트도 숨겨진 내용을 누설하지 않는다.
- 플레이스홀더는 외형을 묘사하지 않고 준비 상태만 설명한다.

## 11. 상태 피드백

모든 데이터 기반 화면은 다음 상태를 구분한다.

| 상태 | 요구 동작 |
|---|---|
| 로딩 | 무엇을 준비 중인지 텍스트로 알리고 중복 실행을 막음 |
| 비어 있음 | 정상적인 빈 상태임을 설명하고 가능한 다음 행동 제공 |
| 잠김 | 잠금 사실과 공개 가능한 이유 제공, 숨겨진 조건은 누설 금지 |
| 오류 | 실패한 작업, 보존된 정보, 재시도 또는 안전 복귀 제공 |
| 완료 | 완료 결과와 다음 문맥 제공 |
| 오프라인 | 정적 앱의 이미 로드된 기능 범위와 자산 실패를 구분하며 온라인 기능을 약속하지 않음 |

과학 데이터가 누락되면 값을 추정해 채우지 않는다. 자산이 누락되면 `docs/09_ASSET_MANIFEST.md`의 지정 플레이스홀더만 사용한다.

## 12. 데이터·명령 경계

UI는 다음 정보를 소비하지만 소유하거나 재계산하지 않는다.

- 현재 Day·페이즈와 허용 전이
- 캐릭터별 호감도 및 관계 단계 판정
- 루트 필수 이벤트와 엔딩 판정
- 미션 상태와 선행 조건
- 인벤토리 수량, 구매·사용 결과
- 공부 상태와 효과
- 시험 정답, 점수, 퇴학 판정
- 원소 1~20 과학 사실
- 갤러리 해금 상태
- 자산 ID와 대체 플레이스홀더

UI가 보내는 명령의 정확한 이름은 State·Systems 계약 후 정한다. 비동기 또는 실패 가능한 명령은 처리 중 중복 입력을 막고 성공 응답 후에만 화면 상태를 확정한다.

## 13. 기술 및 배포 제안

### 13.1 승인 스택

- React
- TypeScript
- Vite
- CSS Modules
- Vitest + React Testing Library
- Playwright
- axe 기반 접근성 검사

이 스택과 테스트 도구는 `APPROVED IMPLEMENTATION DECISION`이다. 추가 UI 키트·상태 라이브러리·라우터는 별도 필요성이 승인되기 전 기본 스택에 포함하지 않는다.

승인된 테스트 책임은 Vitest와 React Testing Library의 단위·컴포넌트 검증, Playwright의 핵심 흐름·GitHub Pages E2E, axe의 자동 접근성 검사다. 자동 axe 결과만으로 접근성 합격을 선언하지 않고 키보드·화면 낭독기 수동 검사를 병행한다.

### 13.2 화면 전환

V1은 URL 라우터 없이 최상위 앱 상태로 화면을 전환한다. 이유는 다음과 같다.

- GitHub Pages의 history 폴백 문제를 피한다.
- URL 직접 진입으로 시험, 저장, 갤러리 가드를 우회할 위험을 줄인다.
- 장면 URL을 저장 상태로 오인하지 않게 한다.

URL 식별이 향후 승인된 요구가 되면 별도 변경 결정으로 해시 라우팅을 검토한다. history 라우팅은 V1 계약이 아니다.

### 13.3 GitHub Pages

- 빌드 산출물은 런타임 서버 없이 동작해야 한다.
- Vite `base` 또는 동등한 빌드 기준을 저장소 하위 경로에 맞춘다.
- 자산은 선행 `/` 없는 매니페스트 상대 경로를 기준으로 해석한다.
- production build를 실제 저장소 하위 경로와 동등한 환경에서 검증한다.
- 필수 비공개 API 키, 인증, 서버 저장을 사용하지 않는다.

### 13.4 의존성 절제

초기에는 라우터, 전역 상태 라이브러리, CSS 프레임워크, UI 키트, 아이콘 패키지를 필수로 두지 않는다. State 계약과 실제 복잡성이 필요성을 입증한 뒤 추가한다.

## 14. 자산 통합 계약

- 런타임은 논리 자산 ID를 참조하고 파일명을 화면에 하드코딩하지 않는다.
- 공개 경로는 `docs/09_ASSET_MANIFEST.md`의 선행 `/` 없는 패턴을 따른다.
- 캐릭터는 현재 `neutral` 플레이스홀더만 전제로 하며 최종 표정 목록을 만들지 않는다.
- 누락 자산은 매니페스트의 `placeholderId`로 대체한다.
- 플레이스홀더는 단색 기하 또는 텍스트 표식처럼 외형 중립이어야 한다.
- 실제 이미지의 원본 크기, 종횡비, 투명도와 안전 영역은 Asset Integration 승인 전까지 유동적으로 수용한다.
- UI 전체를 래스터 이미지로 만들지 않는다.
- 음향 자산·ID·폴더·로딩 상태를 만들지 않는다.

## 15. 미정 의존성

| 담당 | 필요한 계약 |
|---|---|
| Game Systems | 세부 취소 시점, 최종 가격·아이템 사용, 콘텐츠별 미션 조건과 보상 배치 |
| State/Save | 셸 판별, 저장 요약·복구 오류 표현, 명령 결과, `GameState`·`MetaState` 접근 |
| Science | 원소 정본 필드, 공개·비공개 학습 상태, 비교 규칙, 시험 해설 |
| Narrative | 장면·선택지 계약, 대화 기록, 단서 공개 수준, 스포일러 정책, CG 대체 설명 |
| Asset Integration | 이미지 비율·크기·안전 영역, 플레이스홀더 실파일, 대체 텍스트 책임 |
| QA | 지원 브라우저·기기, 성능 예산, 자동·수동 검사 행렬 |

주인공은 사용자 결정으로 남성 고정이다. UI는 이름 입력만 제공하고 `gender = male`을 소비하며 성별 선택을 제공하지 않는다. 남성 확정은 외형 확정이 아니므로 플레이스홀더와 문구가 주인공 외모를 발명하지 않는다.

역할 간 승인 계약은 다음과 같이 정렬됐다.

- 미션은 State와 Systems가 동일한 일곱 상태를 사용하며 UI도 `readyToTurnIn`과 `expired`를 포함해 축약하지 않는다.
- 호감도는 게임플레이 상·하한과 clamp 없이 JavaScript 안전 정수만 검증하며 UI는 유한 최대 게이지를 전제하지 않는다.
- 시험은 고정 10문항·각 10점이다. 시험 중에는 제한된 기본 주기율표 오버레이만 허용하며, 점심과 방과 후는 각각 1행동이고 도달한 시험일 방과 후는 합격 뒤에만 열린다.

## 16. QA 수용 기준

### 16.1 잠금 규칙

- [ ] 모든 활성 게임 화면에서 `DAY NN / 30`과 현재 페이즈를 확인할 수 있다.
- [ ] 일반 Day가 아침 조회, 오전 수업, 점심, 오후 수업, 방과 후, 귀가 순서를 임의로 바꾸지 않는다.
- [ ] 활성 회차가 도달한 Day 10·20·30 시험이 발생하고 일반 메뉴로 우회되지 않으며 Character End 뒤 미래 시험은 표시되지 않는다.
- [ ] 49점은 퇴학, 50점과 100점은 생존으로 표시·전이된다.
- [ ] 호감도 80만으로 필수 미션·이벤트 없이 캐릭터 엔딩 성공을 표시하지 않는다.
- [ ] 날짜 기반 저장을 장면별 자유 저장처럼 표현하지 않는다.
- [ ] 도달한 시험일은 오후 수업 뒤 시험, 합격 후 방과 후 순서다. 효과 직후 Character End를 판정하고 terminal 뒤 미래 시험은 표시하지 않으며, 성공 없이 Day 30 `dayEnd`를 마친 경우 노멀 엔드를 판정한다.
- [ ] 시험 합격 후 체크포인트를 사용자 저장 슬롯으로 표시하지 않고 제출 전·후 복원 차이를 설명한다.
- [ ] 미션 일곱 상태를 누락·병합하지 않고 호감도에 유한 최대 게이지를 사용하지 않는다.
- [ ] 매점이 학교 지도 장소로 나타나지 않고 버튼 인터페이스로만 열린다.
- [ ] 음향 UI와 음향 로딩 코드의 전제가 없다.

### 16.2 갤러리

- [ ] 타이틀에서 갤러리에 접근할 수 있다.
- [ ] 활성 게임 메뉴, VN, 자유시간, 시험, 결과에서 갤러리 링크가 없다.
- [ ] 활성 회차 중 주소·기록·내부 전이 변조로 갤러리를 렌더링할 수 없다.
- [ ] 미해금 CG가 캐릭터·이벤트·조건 스포일러를 노출하지 않는다.
- [ ] 갤러리 탐색이 활성 `GameState`를 변경하지 않는다.

### 16.3 주기율표와 과학

- [ ] 대화식 학습 대상이 원소 1~20으로 제한된다.
- [ ] 족·주기 공간 관계가 데스크톱과 모바일에서 보존된다.
- [ ] 원소 셀과 상세가 같은 과학 정본을 사용한다.
- [ ] 전자배치를 `1`, `2, 6`, `2, 8, 1`과 같은 승인된 전자껍질 표기로 표시한다.
- [ ] H를 알칼리 금속과 동일시하거나 캐릭터 모티프를 과학 사실로 섞지 않는다.
- [ ] 미션·공부에서 주기율표를 열고 원래 문맥으로 돌아올 수 있다.
- [ ] 원소 1~20 핵심 사실은 숙련도와 무관하게 기본 조회되고, 무료 수업만으로 숙련도 2·3이 표시되지 않는다.
- [ ] 숙련도 1·2·3의 체크리스트/필터, 단서/힌트/두 원소 비교, 복합 비교/심화 설명/선택 이해 효과가 구분된다.
- [ ] 시험 중 주기율표는 기본 공간 배열·핵심 사실 상세만 보이고 검색·필터·비교·힌트·진단은 비활성이다.
- [ ] 시험 주기율표를 왕복해도 답안·순서·현재 문항·복귀 포커스가 보존되고 행동 비용·자동 정답·점수 보정이 없다.

### 16.4 반응형과 접근성

- [ ] 소형 세로·가로 화면에서 대사, 선택지, 제출·구매 동작이 가려지지 않는다.
- [ ] 200% 확대에서 핵심 기능을 완료할 수 있다.
- [ ] 키보드만으로 새 게임, 대화, 공부, 주기율표, 미션, 구매, 시험을 완료할 수 있다.
- [ ] 포커스가 화면 전환·모달 닫기 후 예측 가능한 위치에 있다.
- [ ] 잠금·오류·정답·완료 상태가 색상 외 정보로 전달된다.
- [ ] 모션 감소 설정에서 불필요한 장면 전환이 제거된다.
- [ ] 자동 검사와 화면 낭독기 수동 검사를 모두 수행한다.

### 16.5 오류와 배포

- [ ] 저장 없음·손상·이관 가능·복구 불가 상태가 구분된다.
- [ ] 자산 누락 시 승인된 플레이스홀더가 나타난다.
- [ ] 과학 데이터 누락 시 거짓 값을 추정해 표시하지 않는다.
- [ ] 중복 구매·제출·행동 실행을 막는다.
- [ ] GitHub Pages 저장소 하위 경로에서 새로고침과 자산 로딩이 정상 동작한다.

## 17. 알려진 위험

- 승인된 행동 수, 미션 상태, 호감도 검증, 저장 경계, 즉시 Character End와 시험 제한 조회가 정렬됐다.
- Narrative 계획은 거시 비트와 루트 골격만 제안하며 실제 최대 대사·선택지·미션 단서 길이는 미정이므로 극단 콘텐츠 테스트 fixture가 필요하다.
- 자산 비율 미정으로 VN 안전 영역은 유연 레이아웃으로만 계약했으며 실제 자산 통합 때 재검증해야 한다.
- 모바일 주기율표는 공간 관계와 읽기 크기 사이 절충이 필요해 실제 기기 수동 테스트가 중요하다.
- 히든 Ne 루트와 미해금 CG는 일반 잠금 설명 패턴만 사용해도 스포일러가 될 수 있다.
- 조기 Character End는 미래 공통 장면·시험을 건너뛰므로 terminal 이후 내비게이션을 완전히 닫고, 다인 후보 선택 중 이탈·중복 입력에도 하나만 확정되게 해야 한다.
- 무라우터 방식은 GitHub Pages 안정성이 높지만 브라우저 뒤로 가기와 화면 URL 공유를 제공하지 않는다.
