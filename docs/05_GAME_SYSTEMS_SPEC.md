## 3. 원소 1~20 과학 단일 원본

### 3.1 정본 위치와 소비 원칙

구현 시 과학 사실을 담는 런타임 원본은 정확히 하나만 둔다. 권고 논리 이름은 `elements`이며 실제 파일 경로와 형식은 기술 스택 승인 뒤 정한다. `elements.json` 또는 동등한 데이터 모듈 하나가 정본이어야 한다.

- 주기율표, 공부, 미션, 대화, 시험, 캐릭터 프로필은 `elementId`로 정본을 참조한다.
- 소비 데이터는 원자번호, 기호, 이름, 족, 주기, 전자배치를 복제하지 않는다.
- 시험 조건은 예를 들어 “족이 17인 원소 선택”처럼 정본 질의로 답을 계산하거나, 정답 원소 ID만 보유한다. 표시 과학값을 별도 입력하지 않는다.
- 서사 모티프는 캐릭터 정본에 두며 과학 사실 필드와 혼합하지 않는다.
- 정본 데이터 수정은 Science 담당 검토와 모든 소비 영역 회귀 검사를 요구한다.

### 3.2 항목 스키마

| 필드 | 형식·제약 | 의미 |
|---|---|---|
| `id` | `element-01`~`element-20`, 유일·불변 | 참조용 식별자 |
| `atomicNumber` | 정수 1~20, 유일 | 원자번호 |
| `symbol` | 표준 대소문자, 유일 | 원소 기호 |
| `nameKo` | 비어 있지 않은 정본 표기, 유일 | 한국어 원소명 |
| `nameEn` | 비어 있지 않은 정본 표기, 유일 | 영어 원소명 |
| `group` | 정수 1~18 | 현대식 족 번호 |
| `period` | 정수 1~4 | 주기 번호 |
| `shellElectrons` | 양의 정수 배열 | 안쪽부터 전자껍질별 전자 수 |
| `valenceElectrons` | 정수 1~8 | 본 교육 범위의 최외각 전자 수 |
| `teachingTags` | 승인된 태그 ID 배열 | 검색·비교·수업용 분류 |
| `cautionTags` | 승인된 태그 ID 배열 | H 비동일성 등 설명상 주의점 |

파생값은 저장하지 않고 계산한다.

- `shellCount = shellElectrons.length`
- `electronTotal = shellElectrons`의 합
- 표시용 전자배치 = 배열을 `, `로 연결한 문자열
- 기본 검증식: `atomicNumber == electronTotal`, `period == shellCount`

`category`처럼 교육 범위를 넘어 오해를 만들 수 있는 분류는 필수 필드로 두지 않는다. 필요할 때 Science 검토를 거친 제한된 `teachingTags`만 추가한다.

## 4. 학습 진행과 주기율표

### 4.1 학습 주제

| 주제 ID | 핵심 내용 | 주 활용처 |

최종 교과 문구는 Science 검토를 거치며 고급 결합 이론이나 범위 밖 지식을 추가하지 않는다.

### 4.2 숙련도

각 주제는 `0~3` 정수 숙련도를 가진다.

| 숙련도 | 의미 | 시스템 효과 |
|---:|---|---|
| 0 | 미학습 | 원소 1~20 핵심 사실 기본 조회 가능, 단계별 활용 도구 없음 |
| 1 | 소개 | 시험 범위 체크리스트·기초 오답 진단, 족·주기 필터 |
| 2 | 연습 | 대화 해석 단서, 미션 비정답형 힌트, 두 원소 비교 |
| 3 | 숙달 | 복합 비교 도구, 승인 범위 안의 심화 오답 설명, 일부 더 나은 해결·대화 선택의 이해 또는 해금 |

- 숙련도는 정답 자체를 자동 선택하거나 시험 점수를 보정·가산하지 않는다.
- 주기율표의 원소 1~20 핵심 사실인 원자번호·기호·이름·족·주기·전자껍질 분포와 승인된 원자가전자 정보는 일반 플레이에서 처음부터 조회할 수 있다.
- 학습 진행은 사실의 접근 가능성보다 “어떻게 비교하고 활용하는가”를 연다.
- 학습 조건이 붙은 필수 미션은 필요한 주제의 사전 학습 기회를 최소 1회 제공해야 한다.

### 4.3 숙련도 획득

| 행동 | 행동 비용 | 숙련도 변화 | 추가 효과 |
|---|---:|---:|---|
| 하루 수업 주제 선택 | 자유 행동 0 | 선택 주제가 `0`일 때만 `1`; `1` 이상이면 변화 없음 | 오전 소개·오후 복습/진단, 하루 최대 1회 |
| 혼자 공부 | 해당 자유 시간 1 | 선택 주제 `1→2` 또는 `2→3`; `0`이면 먼저 `1` | 복습 피드백 |
| 함께 공부 | 해당 자유 시간 1 | 선택 주제 `1→2` 또는 `2→3`; `0`이면 먼저 `1` | 장면 결과에 따라 명시된 호감도 델타 |
| 미션 학습 보상 | 미션 행동에 포함 | 숙련도 증가 없음 | 단서 적용·복습 피드백만 가능 |

수업 선택은 플레이어가 공부할 화학 주제를 고른다는 잠금 방향을 충족한다. 오전 소개와 오후 복습·진단을 모두 마쳤을 때 해당 주제가 `0`인 경우에만 `1`이 된다. 이미 `1` 이상이면 무료 수업은 체크리스트와 진단만 제공하고 수치를 올리지 않는다. 따라서 매일 무료 수업만으로 일곱 주제를 모두 숙련도 3으로 만들 수 없으며, `2`와 `3`은 반드시 점심·방과 후 행동 슬롯을 소비한다. 시험일에도 같은 수업 흐름 뒤 시험으로 진입하고, 시험 범위는 전날까지 기본 조회 또는 학습 가능했던 주제로 제한한다.

### 4.4 주기율표 도구 동작

- 일반 플레이의 홈 이외 게임 화면에서 필요할 때 열 수 있으며 조회만으로 행동을 소비하지 않는다.
- 원자번호, 기호, 이름, 족, 주기, 전자껍질 분포를 표시한다.
- 숙련도 1부터 족·주기 필터, 2부터 관련 미션의 비정답형 힌트와 두 원소 비교, 3부터 여러 조건의 복합 비교 보기를 제공한다. 대화 단서와 오답 설명은 4.2절 단계 효과를 따른다.
- 힌트는 정답 버튼을 대신 누르지 않고 조건을 좁히는 설명만 제공한다.
- 시험 중에는 행동 비용 없이 주기율표를 열 수 있다. 기본 공간 배열과 원소 1~20 상세의 원자번호, 기호, 한국어·영어 이름, 족, 주기, 전자껍질별 전자배치, 승인된 원자가전자 정보만 제공한다.
- 시험 문맥에서는 검색, 숙련도 기반 족·주기 필터, 두 원소 비교, 복합 비교, 미션·대화 힌트, 오답 진단을 비활성화한다. 조회는 답을 자동 선택하거나 점수를 보정하지 않는다.
- 주기율표 닫기는 호출 전 화면과 선택 상태로 돌아가며 행동·재화·호감도를 바꾸지 않는다.

## 5. 하루와 행동 모델

### 5.1 일반일 단계

일반일:

`아침 조회 → 오전 수업 → 점심 자유 시간 → 오후 수업 → 방과 후 자유 활동 → 귀가/Day 종료`

Day 10·20:

`아침 조회 → 오전 수업 → 점심 자유 시간 → 오후 수업 → 필수 시험 → 합격 시 방과 후 자유 활동 → 귀가/Day 종료`

Character End 없이 도달한 Day 30:

`아침 조회 → 오전 수업 → 점심 자유 시간 → 오후 수업 → 필수 시험 → 50점 미만 terminal / 50점 이상 방과 후 자유 활동 → dayEnd → 노멀 엔드`

활성 회차가 시험일에 도달하면 Day 표시와 필수 시험을 생략할 수 없다. 점심 슬롯은 시험 전에, 방과 후 슬롯은 시험에서 50점 이상을 받은 뒤 제공한다. 50점 미만이면 즉시 퇴학하므로 해당 날짜의 방과 후 슬롯은 사용할 수 없다. Character End 자격은 효과 트랜잭션 직후 판정하되 현재 시험 phase 또는 이미 도달한 필수 시험이 미완료면 합격 완료까지 보류한다. 시험 제출 전에는 방과 후·Day 종료·엔딩으로 이동할 수 없고 퇴학은 엔딩 후보보다 우선한다. Character End가 확정되면 미래 Day와 시험을 실행하지 않는다. 성공 없이 도달한 Day 30은 방과 후 행동과 귀가 처리를 마친 뒤 노멀 엔드를 판정하며 Day 31을 만들지 않는다.

### 5.2 행동 슬롯

- Day 1~30 점심: 행동 슬롯 1개
- Day 1~30 방과 후: 행동 슬롯 1개. 시험일에는 합격 후에만 사용 가능
- 한 일반일 최대 자유 행동: 2개
- 한 회차 최대 자유 행동: `30일 × 2개 = 60개`

슬롯을 소비하는 행동:

- 캐릭터 만나기 또는 관계 이벤트 진행
- 미션 목표 수행 또는 보고
- 혼자 공부 또는 함께 공부
- 장소 기반 학교 활동
- 콘텐츠가 행동 비용 1로 선언한 아이템 사용

슬롯을 소비하지 않는 조작:

- 주기율표 조회
- 미션 목록·인벤토리·상태 확인
- 매점 열기와 단순 구매 수행
- 설정·도움말 확인
- 행동 확정 전 취소

매점 구매는 행동을 소비하지 않지만 재화와 재고 조건을 적용한다. 구매로 시작되는 별도 만남·미션 장면은 실행 전에 행동 1 소비를 명시한다.

### 5.3 행동 처리의 원자성

행동 확정은 다음 순서를 하나의 처리 단위로 수행한다.

1. 현재 Day, phase, 미소비 슬롯, 선행 조건을 검사한다.
2. 예상 비용과 가능한 주요 결과를 표시하고 플레이어가 확정한다.
3. 행동 슬롯을 1회 예약한다.
4. 장면·미션 결과를 확정한다.
5. 호감도, 숙련도, 인벤토리, 플래그를 한 번만 반영한다.
6. 성공 시 슬롯을 소비 상태로 확정한다.
7. 시스템 오류 시 처리 전 상태로 되돌리며 부분 보상을 남기지 않는다.
8. 효과 전체가 성공한 후보 상태에서만 Character End 자격을 계산한다. 시험 보류 조건이 없고 자격이 생기면 10절의 즉시 종료 흐름으로 넘긴다.

같은 행동 ID는 같은 슬롯에서 두 번 보상을 적용할 수 없다.

## 6. 호감도 규칙

### 6.1 상태와 경계

- 초기값: 일곱 캐릭터 모두 `10`
- 저장값: State 계약의 안전 정수. 잠금 규칙에 없는 게임플레이 상·하한은 추가하지 않음
- `<0`: 어색함·관계 악화
- `0~19`: 일반 관계. 단, `10`은 기본 지인 기준점
- `20~39`: 친한 친구
- `40~79`: 연애 긴장·썸
- `80 이상`: 호감도 요건 충족 가능 구간. 필수 조건 없이는 엔드 불가

경계 변화는 델타 적용 후 한 번 평가한다. 단계 진입 이벤트는 같은 경계를 재진입하지 않는 한 중복 발동하지 않는다.

### 6.2 공통 델타 어휘

모든 호감도 변화는 콘텐츠 데이터가 아래 허용값 중 하나를 명시한다. 런타임에서 대사 감정 분석이나 무작위 보정을 하지 않는다.

| 등급 | 델타 | 사용 기준 |
|---|---:|---|
| `major-positive` | `+8` | 필수 개인 사건의 핵심 신뢰·상호성 선택 |
| `strong-positive` | `+5` | 캐릭터 성향에 정확히 맞는 중요한 선택·미션 완료 |
| `positive` | `+3` | 의미 있는 도움·관심 |
| `minor-positive` | `+1` | 작은 배려 또는 낮은 효율의 일상 상호작용 |
| `neutral` | `0` | 반복, 무관, 예의상 반응 |
| `negative` | `-3` | 관계 맥락의 명시적 무시·부주의·배제. 일반적인 타 루트 선택·정중한 불참에는 사용 금지 |
| `strong-negative` | `-6` | 약속 위반, 책임 전가, 명확한 신뢰 훼손 |
| `major-negative` | `-10` | 필수 사건에서의 중대한 배신·강요 |

하나의 선택 결과가 같은 캐릭터에게 여러 델타를 중첩하지 않는다. 다인 이벤트는 캐릭터별로 델타 하나씩 가질 수 있다.

### 6.3 캐릭터별 적용 프로필

| 캐릭터 | 일상·강점 | 손실·반복 제한 |
|---|---|---|
| H | 초반 의미 있는 동행은 주로 `+3`, 개인 사건 핵심은 `+5/+8` | 호감도 40 이상에서 반복 일상 만남은 `0`; 감정 무시·아이 취급은 `-3/-6` |
| C | 직접 교류는 주로 `+1/+3`, 다인 연결·중재 성공은 `+5/+8` | 직접 교류만으로는 필수 다인 이벤트 플래그를 얻지 못함 |
| O | 함께 공부와 상호 노력은 `+3/+5`, 핵심 상호 도움은 `+8` | 답만 요구하거나 노력하지 않으면 `-3/-6`; 단순 정답 수령은 보상 없음 |
| F | 분명하고 일관된 선택은 `+5/+8` | 모호함은 `-3`, 약속 번복은 `-6/-10`; 평균보다 변동 폭이 큼 |
| Na | 참여·다인 사건 해결은 `+3/+5/+8` | 일반 초대 거절·일정 충돌·정중한 불참은 `0`. 관계 맥락에서 지속적 배제, 명시적 약속 파기, 책임 전가, 수락한 공동 계획의 무책임한 이탈만 `-3/-6` 등 승인 델타 허용 |
| Cl | 호감도 20 전 일반 도움은 `+1`, 신뢰 미션은 `+3/+5/+8` | 편법·약속 파기는 `-6/-10`; 초반 일반 선물은 최대 `+1` |
| Ne | 일반 좋은 선택은 `0/+1`, 발견한 특수 사건은 `+5/+8` | 일반 선물은 `0`; 같은 접근 반복은 `0`, 강요·신호 무시는 `-3/-6` |

정확한 이벤트 매핑은 Narrative가 제안하고 Science/Game Systems가 프로필 위반과 도달성을 검토한다.

### 6.4 반복 파밍 방지

- 보상 있는 장면은 안정된 `rewardId`를 가지며 `once`, `oncePerDay`, `repeatableZero` 중 하나를 선언한다.
- 필수 루트 조건은 호감도와 별도 ID 집합으로 관리한다.
- 선물은 아이템·캐릭터 조합별 최초 의미 있는 반응만 보상 가능하며, 이후 동일 조합은 기본적으로 0이다. Narrative가 명시한 예외만 허용한다.
- 호감도 80 도달 시에도 필수 미션·이벤트가 부족하면 관계 단계만 표시하고 엔딩 후보로 만들지 않는다.
- Ne의 일반 대화·일반 선물만으로 얻을 수 있는 총 호감도는 80에 도달할 수 없도록 정적 합계 검사를 둔다.

### 6.5 제안 단계 수치 도달성 예산표

아래 수치는 상세 대본·최종 콘텐츠가 아니라 구현 전 데이터 정적 검증 계약이다. 모든 루트는 시작 호감도 10에서 계산하며 `필수 체인 행동`, `보조 관계 행동`, `시험 공부 행동`을 모두 자유 행동으로 계상한다. 수업에서 얻는 무비용 숙련도는 이 표의 시험 공부 행동을 줄이는 근거로 사용하지 않는다. 이 예산의 양수 호감도 델타에는 `+1`, `+3`, `+5`, `+8`만 허용한다.

| 루트 | 필수 이벤트·미션 | 최초/최종 완료 가능 Day | 해당 시점까지 필수 합격 시험 | 필수 체인 행동·델타 합 | 보조 관계 경로 | 시험 공부 | 시작→최종 | 집중 경로 자유 행동 |
|---|---|---:|---|---:|---:|---:|---:|---:|
| H | `H-E1/H-M1/H-E3/H-E4/H-E5` | 27 / 29 | Day 10·20 | 14행동, `+3+8+5+8+8=+32` | 10행동: `4×+5 + 6×+3 = +38` | 9 | `10+32+38=80` | 33 |
| C | `C-E1/C-M1/C-E3/C-M2/C-E5` | 27 / 29 | Day 10·20 | 16행동, `+3+8+8+8+8=+35` | 7행동: `7×+5 = +35` | 9 | `10+35+35=80` | 32 |
| O | `O-E1/O-M1/O-E3/O-M2/O-E5` | 27 / 29 | Day 10·20 | 16행동, `+3+8+5+8+8=+32` | 8행동: `8×+5 = +40` | 9 | `10+32+40=82` | 33 |
| F | `F-E1/F-M1/F-E3/F-E4/F-E5` | 27 / 29 | Day 10·20 | 14행동, `+5+8+5+8+8=+34` | 5행동: `5×+8 = +40` | 9 | `10+34+40=84` | 28 |
| Na | `Na-E1/Na-M1/Na-E3/Na-M2/Na-E5` | 27 / 29 | Day 10·20 | 17행동, `+3+8+5+8+8=+32` | 8행동: `8×+5 = +40` | 9 | `10+32+40=82` | 34 |
| Cl | `Cl-E1/Cl-M1/Cl-E3/Cl-M2/Cl-E5` | 27 / 29 | Day 10·20 | 18행동, `+1+8+5+8+8=+30` | 8행동: `8×+5 = +40` | 9 | `10+30+40=80` | 35 |
| Ne | `Ne-E0/Ne-E1/Ne-M1/Ne-E3/Ne-E4` | 27 / 29 | Day 10·20 | 16행동, `E0 보상 없음; +5+8+8+8=+29` | 일반 12행동 `12×+1=+12`; 해금 후 특수 4행동 `4×+8=+32` | 9 | `10+29+12+32=83` | 41 |

시험 공부 9행동은 각 시험 전에 3행동씩 확보하는 공통 검증 경로다. 무료 일과 수업의 `0→1` 소개나 `1+` 복습·진단으로 대체하거나 줄일 수 없다. 최종 밸런싱에서 더 적은 공부로도 합격할 수는 있지만, 루트 도달성 테스트 fixture는 이 보수적 예산을 사용한다.

Ne 분리 증명:

- 일반 대화는 회차당 보상 가능한 서로 다른 항목을 최대 12개로 제한하고 각각 `+1`, 일반 선물은 종류·횟수와 무관하게 `0`이다.
- 일반 대화·선물의 전체 최대 호감도 보상은 `+12`이고 시작값 포함 최대 호감도는 `10+12=22`로 80 미만이다.
- 결정적 단서, 18족 비교 미션, 거리 존중 사건, Ne의 제안으로 이어지는 특수 필수 체인은 `+29`, 해금 뒤 특수 상호작용 네 개는 `+32`다. 일반 최대와 함께 완료하면 `10+12+29+32=83`으로 80 이상이다.
- 특수 보상은 일반 대화·선물 ID로 재분류할 수 없고 필수 체인 선행 조건 없이는 실행할 수 없다.

정적 수용 조건:

- 각 집중 경로의 `필수 체인 + 보조 관계 + 시험 공부` 합은 42행동 이하여야 한다.
- 각 경로는 총 60행동에서 18개 이상을 복구·다른 학교생활 여유로 남겨야 한다.
- 개별 호감도 보상은 `+1`, `+3`, `+5`, `+8`만 사용하고 표의 합계와 일치해야 한다.
- 필수 체인의 행동 수에는 무보상 목표 수행·보고가 포함될 수 있다. 최종 데이터 검사는 보상 항목뿐 아니라 소비 행동 전체의 합이 표와 일치하는지도 검증한다.
- 필수 이벤트·미션 ID는 `docs/04_NARRATIVE_PLAN.md`의 골격과 일치하고 순환 의존성이 없어야 한다.
- 최종 콘텐츠가 행동 수나 합계를 바꾸면 이 표와 `docs/04`의 수치 연결표를 함께 갱신하고 QA 재검토 전 구현할 수 없다.
- 최종 데이터는 각 루트의 `earliestCompletionDay`를 Day/phase·선행 조건·슬롯 배치에서 계산하고 29 이내인지 검사한다. 그 Day까지 도달한 시험은 모두 제출·합격이어야 하며 미래 시험은 선행 조건에서 제외한다.
- `earliestCompletionDay`까지 실제 이용 가능한 점심·방과 후 슬롯 안에 필수 체인, 보조 관계, 시험 공부 행동이 모두 배치되는지와 각 보상 합을 함께 검사한다. 회차 전체 60개만으로 도달성을 증명해서는 안 된다.

## 7. 미션 상태 머신

### 7.1 상태

| 상태 | 의미 | 종결 여부 |
|---|---|---|
| `locked` | 선행 조건 미충족, 플레이어에게 비공개 | 아니요 |
| `available` | 제시 조건 충족, 수락 가능 | 아니요 |
| `active` | 수락되어 목표 수행 가능 | 아니요 |
| `readyToTurnIn` | 모든 필수 목표 충족, 보고 대기 | 아니요 |
| `completed` | 보상과 플래그가 정확히 한 번 반영됨 | 예 |
| `failed` | 명시한 실패 조건 충족 | 예 |
| `expired` | 명시한 기한을 넘김 | 예 |

### 7.2 허용 전이

| 현재 | 사건 | 다음 | 필수 검사·효과 |
|---|---|---|---|
| `locked` | 공개 조건 충족 | `available` | Day·플래그·학습 조건 검사 |
| `available` | 수락 | `active` | 수락 시 지급 아이템을 원자적으로 지급 |
| `active` | 목표 일부 충족 | `active` | 목표 카운터만 갱신, 완료 보상 없음 |
| `active` | 모든 필수 목표 충족 | `readyToTurnIn` | 보고 대상·시간대 공개 |
| `readyToTurnIn` | 유효하게 보고 | `completed` | 요구 아이템 소비 후 보상·플래그 1회 반영 |
| `available/active/readyToTurnIn` | 명시된 실패 선택 | `failed` | 실패 결과를 1회 반영 |
| `available/active/readyToTurnIn` | 만료 시점 통과 | `expired` | 만료 결과를 1회 반영 |

그 밖의 전이는 거부한다. `completed`, `failed`, `expired`에서 같은 미션을 재보상하지 않는다. 재도전이 필요하면 원래 미션을 되돌리지 않고 별도의 후속 또는 재시도 미션 ID를 연다.

### 7.3 미션 데이터 계약

각 미션은 최소 다음 역할을 가진다.

- 안정된 `missionId`
- 소유 캐릭터 또는 공통 분류
- `requiredForRoute` 여부와 연결 `routeId`
- 공개·수락·완료·실패·만료 조건
- 가능한 Day 범위, phase, 장소
- 목표 목록과 각 목표의 판정 방식
- 필요한 `topicId`, `elementId`, 아이템 ID 참조
- 수락 시 지급, 완료 시 소비, 완료·실패 보상
- 호감도 `rewardId`와 델타 등급
- 완료 시 설정할 필수 이벤트 ID
- 플레이어용 단서와 보고 대상

과학 미션은 과학값을 직접 쓰지 않고 원소 ID와 조건을 참조한다. 예를 들어 “2주기 17족 찾기”는 `group == 17 && period == 2` 질의를 사용하며 답을 서사 파일에서 `F`라는 사실값으로 재정의하지 않는다.

### 7.4 필수 미션 안전 규칙

- 필수 루트 미션은 무작위 등장·무작위 성공을 사용하지 않는다.
- 필수 미션이 만료될 수 있으면 만료 전 최소 2개의 유효 행동 기회를 제공하고 명확한 기한을 표시한다.
- 필수 미션의 `failed/expired`가 루트를 영구 차단한다면 실패를 확정하는 선택 전에 경고한다. 권고안은 별도 재시도 미션으로 복구 가능하게 하는 것이다.
- 필요한 과학 지식은 주기율표에서 조회 가능하고, 숙련도 조건이 있으면 사전 학습 기회가 있어야 한다.
- 필수 아이템은 판매·선물·다른 미션 소비 대상으로 사용할 수 없다.
- 순환 선행 조건을 금지한다.

## 8. 인벤토리와 매점

### 8.1 인벤토리

아이템 분류:

- `gift`: 선물
- `mission`: 미션 전용 물건
- `school`: 일반 학교생활 물건
- `study`: 공부 관련 물건

규칙:

- 장비 슬롯, 능력치 장착, 무게, 내구도, 전투 수치는 없다.
- 수량은 0 이상의 정수이며 0이 되면 목록에서 숨길 수 있다.
- `stackable` 아이템은 동일 ID 수량으로 합치고, 고유 미션 물건은 `unique`로 관리한다.
- 아이템 효과는 데이터에 명시된 사용 맥락에서만 적용한다.
- 사용·전달·구매는 조건 검사, 수량 변경, 결과 적용을 하나의 원자적 처리로 수행한다.
- 미션 예약 아이템은 해당 미션 완료·실패 처리 전까지 다른 곳에 소비할 수 없다.
- 인벤토리 용량 제한은 두지 않는다.

### 8.2 재화와 매점 제안

- 재화 논리 이름: `funds`
- 시작 소지금: `3,000` (`APPROVED IMPLEMENTATION DECISION`)
- 가격은 0 이상의 정수이며 구매 시 `funds >= price * quantity`여야 한다.
- 일반 가격 권고 범위는 `300~1,200`이며 최종 카탈로그는 별도 유예다.
- 구매 성공 시 재화를 정확히 한 번 차감하고 수량을 정확히 한 번 늘린다.
- 잔액 부족, 판매 기간 전후, 선행 조건 미충족이면 상태를 바꾸지 않는다.
- V1에서는 판매, 흥정, 확률 할인, 랜덤 재고, 복잡한 재고 회복을 사용하지 않는다.
- `oncePerRun` 상품은 구매 후 다시 살 수 없고, 일반 상품은 무한 재고로 취급할 수 있다.
- 매점 UI 열기와 구매는 자유 행동을 소비하지 않는다.

### 8.3 경제 안전 조건

- 필수 루트 구매품의 총 최소 비용은 해당 시점까지 확정적으로 획득 가능한 재화 이하여야 한다.
- 하나의 집중 루트가 필수로 요구하는 매점 비용 권고 상한은 시작 소지금의 50%인 `1,500`이다.
- 필수 미션 물건을 잘못 구매하는 함정을 만들지 않는다. 단서로 후보를 비교하게 할 수는 있으나 정답 판정에 필요한 정보는 조회 가능해야 한다.
- 일반 선물 반복은 재화만 있으면 무한 호감도를 만드는 수단이 될 수 없다.

## 9. 시험 시스템

### 9.1 시험 일정과 범위

| 시험 | 문항 | 배점 | 제안 범위 |
|---|---:|---:|---|
| Day 10 | 10 | 각 10점 | 원자번호·기호·이름, 족·주기 기초, 전자껍질 분포 읽기 |
| Day 20 | 10 | 각 10점 | Day 10 누적 + 족·주기 비교, 원자가전자, 같은 족의 유사 경향 |
| Day 30 | 10 | 각 10점 | 전체 누적 + 안정한 전자배치, 여러 조건의 복합 비교 |

- 모든 문항은 1~20 정본과 승인된 학습 주제만 사용한다.
- 각 시험의 최종 문항 ID와 순서는 고정한다. 선택지 순서도 V1에서는 고정해 저장·복구를 단순화한다.
- 게임에서 사전에 소개하거나 주기율표로 조회할 수 없는 사실을 요구하지 않는다.
- 고급 화학, 범위 밖 원소, 전문 상수 암기는 출제하지 않는다.

### 9.2 문항 계약

각 문항은 최소 다음 정보를 가진다.

- 안정된 `questionId`와 `examId`
- 하나 이상의 `topicId`
- 참조 `elementId` 또는 정본 질의
- 질문 형식과 선택지 ID
- 정답 선택지 ID 또는 정본으로 계산 가능한 정답 조건
- 10점 배점
- 오답·정답 해설이 참조할 과학 사실 키
- 교육 범위 검토 상태

문항 문구에 표시값이 필요하면 정본에서 삽입한다. 원자번호·족·전자배치를 문항 데이터에 독립 사실로 중복 저장하지 않는다.

### 9.3 시험 흐름

1. 해당 Day의 강제 시험 단계에 진입한다.
2. 시험 범위, 10문항, 100점 만점, 50점 미만 즉시 퇴학과 제한된 기본 주기율표 조회 가능 범위를 알린다.
3. 문항을 순서대로 풀되 제출 전에는 자유롭게 답을 변경할 수 있다.
4. 미응답 문항이 있으면 제출 확인에서 경고한다. 그래도 제출하면 미응답은 오답이다.
5. 제출을 한 번 확정하면 정답 수를 계산하고 `score = correctCount * 10`으로 채점한다.
6. 점수와 제출 결과를 해당 Day 시험 ID에 한 번만 기록하는 후보 상태를 만든다.
7. `score < 50`이면 같은 제출 전이에서 `terminal/expelled`를, `score >= 50`이면 같은 Day `examResolved/afterSchoolFreeTime`을 시스템 강제 체크포인트로 즉시 원자 커밋한다.
8. 커밋 성공 뒤에만 실패 결과 또는 합격 결과·문항별 해설을 제공한다. 합격 시 보류 후보가 없을 때만 같은 Day 방과 후로 가고, 보류 후보가 있으면 다른 행동 없이 즉시 엔딩 후보 흐름을 재개한다.
9. 각 시험 효과 커밋 뒤 보류 중인 Character End 자격을 평가한다. 합격이면 후보 흐름을 진행할 수 있고, 실패면 후보보다 퇴학을 우선한다. Character End 없이 Day 30 방과 후와 `dayEnd`를 마치면 노멀 엔드를 판정한다.

시험에서 주기율표를 여는 동안 `answersByQuestion`, 고정 문항·선택지 순서, 현재 문항 위치를 런타임에 그대로 유지한다. 닫으면 같은 문항으로 돌아오며 조회 자체는 시험 상태·점수·행동 슬롯을 바꾸지 않는다. 이 오버레이 문맥은 새 저장 체크포인트가 아니다.

재응시와 점수 덮어쓰기는 없다. 저장·새로고침으로 제출 여부나 결과를 되돌려 시험을 우회할 수 없어야 한다.

### 9.4 시험 수용 예

| 입력 | 기대 결과 |
|---|---|
| 판정 대상 점수 49 | 즉시 퇴학 |
| 판정 대상 점수 50 | 생존, 다음 단계 |
| 판정 대상 점수 100 | 생존, 다음 단계 |
| 10문항 중 4개 정답 | 40점, 퇴학 |
| 10문항 중 5개 정답 | 50점, 생존 |
| 10문항 중 10개 정답 | 100점, 생존 |
| Day 20 시험 미완료 상태에서 Day 종료 요청 | 거부, 시험으로 복귀 |
| 이미 제출된 시험 재제출 | 거부, 기존 결과 유지 |

10점 단위 문항 구조에서는 실제 생성 점수 49가 나오지 않지만, 잠금 경계 보장을 위해 합격 판정 자체는 임의 정수 입력 `49/50/100`으로 별도 단위 검증한다.

## 10. 엔딩 판정

**상태:** 결정 020의 즉시 Character End 계약 승인. 상세 장면·콘텐츠·코드 구현은 별도 게이트다.

### 10.1 판정 순서

1. 행동·이벤트 효과의 비용, 보상, 호감도, 미션·이벤트 플래그와 route-ending condition을 하나의 트랜잭션으로 완전히 반영한다.
2. 현재 시험 phase 또는 이미 도달한 필수 시험이 미완료면 이번 효과로 생긴 자격 후보와 효과 ID를 보존하고 후보 확정을 보류한다.
3. 보류 조건이 없으면 효과 완료 직후 모든 캐릭터의 자격을 계산하되 이번 단일 효과로 새 자격을 얻은 후보 집합을 구한다.
4. 새 후보가 0명이면 일반 진행을 계속한다.
5. 새 후보가 1명이면 해당 캐릭터의 실패 없는 최종 장면을 재생한다.
6. 하나의 다인 이벤트로 새 후보가 2명 이상이면 그 후보만 표시하고 플레이어가 정확히 한 명을 선택한다.
7. 선택 또는 단일 후보의 최종 장면 뒤 선택한 결말 하나, terminal GameState, 관련 CG·결말 MetaState를 원자 커밋한다. 선택하지 않은 후보의 엔딩은 확정·해금하지 않는다.
8. terminal 커밋 뒤 미래 Day·시험·행동은 실행하지 않는다.
9. 시험 제출로 보류를 해제할 때 `score < 50`이면 보류 후보를 폐기하고 퇴학을 우선한다. 합격이면 저장된 동일 후보 집합으로 단일·복수 후보 흐름을 즉시 재개하며 그 전에 다른 행동을 허용하지 않는다.
10. Character End 없이 Day 30 시험 합격, 방과 후, `dayEnd`를 모두 마치면 노멀 엔드를 terminal로 커밋한다.

### 10.2 캐릭터 엔드 자격

캐릭터 `c`의 자격은 다음 조건의 논리곱이다.

```text
affection[c] >= 80
AND every requiredMissionId[c] is completed
AND every requiredEventId[c] is completed
AND routeEndingCondition[c] is true
```

자격 획득 뒤 최종 장면에는 결과를 뒤집는 숨은 실패·추가 조건·호감도 손실을 두지 않는다. 호감도 100이어도 필수 미션 하나가 미완료면 자격이 없고, 나머지 조건이 모두 완료돼도 호감도 79면 자격이 없다.

### 10.3 우선순위 판정표

| 문맥 | 후보 수 | 기대 결과 |
|---|---:|---|
| 도달한 필수 시험 미완료 또는 현재 `exam` | 무관 | 자격 판정 보류, 시험 우회 금지 |
| 시험 제출 점수 49 이하 | 무관 | 후보보다 퇴학 게임 오버 우선 |
| 효과 완료, 보류 없음 | 0 | 일반 진행 계속 |
| 효과 완료, 보류 없음 | 1 | 해당 후보 최종 장면 후 Character End 원자 커밋 |
| 하나의 다인 효과 완료, 보류 없음 | 2 이상 | 새 자격 후보만 선택, 정확히 하나의 Character End 원자 커밋 |
| Day 30 합격·방과 후·`dayEnd` 완료 | 0 | 노멀 엔드 |

## 11. 역할 간 논리 계약

### Narrative가 제공할 것

- 장면·미션·이벤트의 안정된 ID
- 각 루트의 필수 미션·이벤트 ID 목록
- 시간대·장소·선행 조건
- 선택 결과별 공통 호감도 델타 등급
- `rewardId` 반복 정책
- 실패·만료·재시도와 최종 결말 장면

### State/Save가 보존할 것

- 현재 Day와 phase, 점심·방과 후 슬롯 소비 여부
- 캐릭터별 호감도와 적용된 `rewardId`
- 주제별 숙련도
- 미션 상태, 목표 진행, 보상 적용 여부
- 인벤토리 수량, 예약 아이템, 재화, 구매 이력
- 시험 답안·제출 여부·점수·완료 여부
- 루트·이벤트 플래그, run status, 확정 엔딩

저장은 사용자 관점의 Day 시작 스냅샷이 기본이다. 제출 전 종료는 같은 Day 시작과 같은 고정 문항·순서로 돌아간다. 합격 제출은 같은 Day `afterSchoolFreeTime`의 시스템 강제 `examResolved`, 실패 제출은 `terminal`로 즉시 원자 커밋하며, 이는 사용자 임의 장면 저장 슬롯이 아니다.

### UI/UX가 표시할 것

- `DAY n / 30`, 현재 phase, 남은 자유 행동
- 행동 확정 전 시간 비용
- 조회와 실제 행동의 차이
- 주기율표 정본 정보와 숙련도 기반 비교 도구
- 미션 상태·기한·목표·보고 가능 여부
- 아이템 수량, 예약 상태, 가격, 잔액, 거래 실패 이유
- 시험 규칙, 미응답 경고, 결과와 해설
- 즉시 엔딩 안내, 동시 복수 후보 선택, 실패 없는 최종 장면과 terminal 저장 결과
- 시험 중 제한된 기본 주기율표와 동일 문항 복귀

### QA가 검증할 것

- 과학 정본 무결성과 소비 도메인의 비복제 참조
- 행동 1회당 슬롯·보상 정확히 1회 처리
- 호감도 경계와 캐릭터별 반복 제한
- 미션의 허용·금지 전이 및 필수 미션 도달성
- 구매·아이템 사용의 원자성 및 경제 교착 없음
- 실제 도달한 Day 10/20/30 시험 강제와 `49/50/100`, terminal 뒤 미래 시험 미실행
- 효과 직후 자격, 시험 보류·퇴학 우선, 복수 후보 정확히 하나, Day 30 노멀 엔드와 세 결과의 도달성

## 12. 가정, 비차단 의존성, 유예

### 가정

- 캘린더는 Day 1~30의 점심·방과 후 슬롯을 반영해 회차 최대 자유 행동을 60개로 유지한다. 시험일 방과 후는 합격한 경우에만 열린다.
- 시험 점수는 플레이어 답안으로만 정하며 숙련도·호감도·아이템 보너스를 더하지 않는다.
- 미션과 관계 보상은 확률을 사용하지 않는다.
- 시작 소지금은 `3,000`, 숙련도는 `0~3`으로 승인됐다. 호감도에는 잠금 규칙에 없는 상·하한이나 clamp를 추가하지 않고 JavaScript 안전 정수 범위만 검증한다.

### 비차단 의존성

주인공은 사용자 결정으로 남성 고정이며 `player.gender = male`이다. 이름은 사용자 입력이고 성별 선택·성별 기반 수치 보정은 없다. 마스터가 기존에 pending을 요구한 이유는 상충 진술의 임의 해소를 막기 위해서였으며 사용자 결정으로 해소됐다. 캐릭터 외형 유예는 유지한다.

### 유예

- 최종 30일 수업표
- 최종 시험 문항 은행
- 최종 미션과 아이템·매점 카탈로그
- 루트별 최종 데이터 ID와 개별 보상 배치. 총 행동·보상 수용값은 6.5절 계약을 따른다.
- 캐릭터 엔딩 장면과 CG 목록

유예 항목은 본 상태·참조 계약에 맞춰 후속 제안하며, 임의 확정하지 않는다.

## 14. QA 위험과 차단 기준

다음은 승인 또는 구현을 차단해야 한다.

- 과학 사실이 원소 정본 외 콘텐츠에 독립 값으로 중복되어 불일치 가능성이 생김
- 1~20 밖 원소나 고급 화학이 필수 미션·시험 정답에 필요함
- 수업·주기율표·미션·시험 중 하나가 다른 전자배치 표기를 사용함
- 필수 미션이 무작위, 순환 의존성, 소진 가능한 필수품 때문에 도달 불가능함
- 반복 대화·선물만으로 필수 루트 조건 또는 Ne 특수 조건을 우회함
- 호감도 80만으로 캐릭터 엔드가 열리거나 80+필수 조건인데도 엔드 후보가 되지 않음
- 저장·불러오기·새로고침으로 실제 도달한 Day 10/20/30 시험을 건너뜀
- 49가 생존하거나 50이 퇴학 처리됨
- 도달한 필수 시험이 미완료인데 Character End를 판정하거나 시험 실패보다 후보를 우선함
- 노멀 엔드, 캐릭터 엔드, 퇴학 게임 오버 중 하나가 도달 불가능함
- 무료 일과 수업 또는 미션 보상만으로 숙련도 2·3을 얻거나 시험 공부 9행동을 대체함
- 숙련도가 시험 점수·정답을 자동 보정하거나 1~20 핵심 사실 접근을 막음
- Na의 일반 타 루트 선택·정중한 불참에 음수 호감도를 적용함
- 시험 중 검색·숙련도 도구·비교·힌트·진단을 제공하거나 주기율표 왕복으로 답안·현재 문항을 잃음
- 효과 트랜잭션 완료 전 자격을 계산하거나 동시 후보 둘 이상을 확정하거나 terminal 뒤 미래 시험을 실행함

## 15. 승인 상태와 후속 게이트

점심·방과 후 각 1행동, GS-REV-01의 숙련도 0~3 획득·효과, 시험별 고정 10문항·문항당 10점, 호감도 무상한 안전 정수, 미션 7상태, 시작 소지금 3,000, 결정 020의 즉시 Character End, 결정 021의 시험 중 제한 기본 조회는 `APPROVED IMPLEMENTATION DECISION`이다.

조회·구매의 행동 비용 0, 7개 학습 주제 구성, 최종 미션·이벤트·문항·아이템·가격·개별 보상 배치는 계속 `PROPOSAL`이며, 6.5절 정적 예산과 과학·캐릭터 검수를 통과해야 한다. 본 계약 반영만으로 코드 구현이 자동 승인되는 것은 아니며 QA 재검토 게이트를 따른다.
